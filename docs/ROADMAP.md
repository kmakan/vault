## Фаза 2: Шифрование на стороне клиента
**Статус**: Базовое шифрование готово, нужна E2E интеграция

### Архитектура:
```
Отправитель (Alice):
  1. Вводит сообщение
  2. Шифрует СВОИМ ключом (Alpha + Columnar + Noise)
  3. Отправляет через SMTP
  
Получатель (Bob):
  1. Проверяет IMAP
  2. Находит письмо с маркером [WHISPER]
  3. Расшифровывает СВОИМ ключом
  4. Показывает в интерфейсе
```

## Фаза 3: Обмен контактами (QR/ID)
**Статус**: Не начат

### Как работает (как в Session):
```
1. Alice хочет написать Бобу
2. Alice сканирует QR-код Боба (или вводит его ID)
3. Vault создаёт зашифрованный канал
4. Alice пишет сообщение
5. Vault шифрует ключом Алисы
6. Bob получает → расшифровывает ключом Боба
```

### QR-код содержит:

## Технические решения

### Шифрование:
- **Alpha Cipher** — замена символов (быстро, но слабо)
- **Columnar Transposition** — перестановка (средне)
- **Combined** — Alpha + Columnar (рекомендуется)
- **Noise** — защита от анализа (добавлять всегда)

### Маркировка писем:
- **Тема**: `[WHISPER] <зашифрованная тема>` или просто `[WHISPER]`
- **Заголовок**: `X-Vault: <version>` (опционально)
- **Тело**: зашифрованный текст в формате Vault

### Обмен ключами:
- **QR-код**: ID + публичный ключ (как Session)
- **По ID**: ручной ввод ID (как Telegram)
- **Через email**: отправить зашифрованный ключ (доп. безопасность)
