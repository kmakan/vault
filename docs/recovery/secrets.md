# Секреты релея: что нужно, где лежит, что будет при потере

Значений здесь нет и быть не должно — только имена, назначение и порядок
действий. Файлы на сервере: `~/vault-relay/env` (0600) и
`~/vault-relay/accounting.env` (0600).

| переменная | зачем | если потеряна |
|---|---|---|
| `VAULT_RELAY_KEY` | HMAC-ключ выданных кодов/токенов | **Менять нельзя.** Новый ключ обнулит все выданные коды: люди с оплаченным Pro останутся без доступа. Доставать только из бэкапа |
| `VAULT_RELAY_ADMIN_KEY` | доступ к `/admin/*` (служебные вызовы с localhost) | Перевыпускается: меняем значение и в скриптах на ноутбуке |
| `VAULT_RELAY_ANON_PUB` | публичный ключ анонимного режима | Перевыпускается вместе с клиентской парой |
| `VAULT_RELAY_UNLIMITED_KEY` | безлимит для служебных аккаунтов | Перевыпускается |
| `VAULT_RELAY_KEEP_CLAIM` | сколько держать claim-запись | Не секрет, значение по умолчанию из кода |
| `VAULT_RELAY_FREE_DAILY_LIMIT` | порог сообщений для free | Не секрет, задаётся числом |
| `VAULT_RELAY_STATE` | путь к `vault-relay-state.json` | Не секрет |
| `VAULT_RELAY_ACCOUNTING` | путь к `vault-relay-accounting.json` | Не секрет |
| `VAULT_RELAY_ADDR` | адрес прослушивания (`127.0.0.1:8091`) | Не секрет |
| `VAULT_RELAY_PUBLIC_URL` | публичный адрес для ссылок оплаты | Не секрет |
| `VAULT_RELAY_PAYMENTS` | включены ли платежи (`yookassa`) | Не секрет |
| `VAULT_RELAY_REQUIRE_SIG` | требовать ли подпись запросов | Не секрет |
| `VAULT_RELAY_NTFY_URL` | канал пушей | Перевыпускается |
| `VAULT_RELAY_YOOKASSA_SHOPID` | номер магазина ЮKassa | **Есть локально** в `~/.config/vault-relay/npd.env` |
| `VAULT_RELAY_YOOKASSA_SECRET_KEY` | секретный ключ ЮKassa | **Есть локально** там же; при компрометации перевыпускается в кабинете |
| `VAULT_RELAY_YOOKASSA_API` | базовый URL API | Не секрет |
| `VAULT_RELAY_CRYPTO_API` / `_APIKEY` | платёжный провайдер крипты | Ключ перевыпускается у провайдера |
| `VAULT_RELAY_CRYPTO_IPN_SECRET` | подпись уведомлений крипто-провайдера | Перевыпускается у провайдера |
| `VAULT_NPD_REFRESH_TOKEN` | токен «Мой налог» для чеков | **Есть локально** в `npd.env`; перевыпускается входом в ЛКФЛ |

## Что это значит на практике

1. **Критичен один секрет — `VAULT_RELAY_KEY`.** Всё остальное либо не секрет,
   либо перевыпускается за минуты. Поэтому при восстановлении сервера первым
   делом ищем именно его: в `env`, в бэкапах `~/backups/vault-relay/*/env`, в
   истории `~/vault-relay/env.bak-*`.
2. Если `VAULT_RELAY_KEY` потерян безвозвратно — придётся выпускать ключ заново
   и предупредить покупателей Pro, что код нужно получить заново в приложении.
   Это неприятно, но не смертельно: подписки в `state.json` привязаны к
   отпечаткам устройств, а не к самому ключу.
3. Пароли приложений почты (`vault-msg@ya.ru` и бот `vault_msg@bk.ru`) лежат в
   `~/Notes/Projects/mailcipher/mails.md` — они не на сервере и не потеряются.
