# ADR-007: Репозитории, приложения и магазины

**Дата**: 21.11.2026; пересмотрено 25.11.2026
**Статус**: принято, разделение репозиториев утверждено владельцем
**Основание**: указание владельца 21.11.2026 — проект будет расширяться;
решение владельца 25.11.2026 — мессенджер самостоятелен, соцсеть и будущие
части зависят от основного приложения и размещаются в своих репозиториях.
**Связанные документы**: ADR-004 (модульная независимость), ADR-005 (граница
Rust/JS), ADR-006 (архитектура Sfera), `docs/design/feature-service-map.md`.

---

## 1. Решение в одном абзаце

Каждый продукт — **отдельное приложение и отдельный репозиторий** со своим
workspace, версией, тегом, подписью и листингом в магазине. Мессенджер —
самостоятельная образующая часть проекта. Sfera и будущие части — зависимые
приложения: они используют контакты и публичные возможности основного
приложения через версионируемые порты, но не меняют его поведение. Общий код —
только явно версионируемые библиотеки; прикладной код не импортируется между
приложениями. Взаимодействие — E2E-конверты, deep link и разрешённый общий
key store на устройстве. Разделение физически выполняется с сохранением
истории и проверкой границ, а не копированием каталога с потерей git-истории.

---

## 2. Как независимость сохраняется между репозиториями

| Зависимость | Правило |
|---|---|
| Версии и релизы | Независимы по репозиториям, тегам, CI и артефактам |
| Права доступа | Можно открыть/выдать доступ к одному продукту без остальных |
| Общий код | Только версионируемая библиотека с явным контрактом; никаких path-ссылок через соседний репозиторий |
| Контакты и ключи | Мессенджер владеет ими; Sfera получает публичную часть через link/порт, приватные ключи не копируются |
| Изменение фичи | Не меняет чужой репозиторий; смена общего контрата — версия + прогон потребителей |

Изменение общей библиотеки требует явной версии и зелёных потребителей, но
изменение комментариев, профиля, ленты или другой фичи Sfera не требует коммита
в мессенджер. Vue/JS остаются фронтом и тонким адаптером; формат, подписи,
права, состояние и доставка — Rust.

## 3. Как устроены части проекта

```
whisper/                      # monorepo, один git
  vault-core/                 # общая библиотека: crypto, identity, key_store,
                              # relay, settings, transport. Версионируется.
  vault-client/               # мессенджер: CLI + ядро обмена (свой workspace)
  vault-desktop/              # мессенджер: Tauri (desktop + Android)
  vault-relay/                # сервер доставки
  sfera/                      # соцсеть: свой workspace (38 крейтов + UI + shell)
    crates/
    src/
    src-tauri/
```

Правила, которые уже действуют и не меняются при росте:

1. **Приложение ≠ крейт ≠ сервис.** Крейт — единица логики; приложение —
   установочный пакет; сервис — процесс с сетевым контрактом. Видеохостинг и
   стриминг сначала появляются как крейты Sfera, затем могут стать сервисами
   (ADR-006 §9.2), но не «второй вкладкой».
2. **Стрелки зависимостей.** `feature → vault-core | social-model |
   social-rights`; `feature ↛ feature`; `social-app → все`; `social-ffi →
   social-app`. Между приложениями — **ноль** импортов прикладного кода.
3. **Общее — только в `vault-core`.** Если функция нужна обоим приложениям,
   она сначала переезжает в ядро (аддитивно, с реэкспортом), а не подключается
   «как есть» из чужого приложения.
4. **Идентичность одна на уровне аккаунта, но не через копию ключа.** У Sfera
   свой ключ устройства и сертификат, выданный аккаунтом; приватный ключ
   мессенджера между приложениями не передаётся (ADR-006 §8). Связывание — по
   QR/`vault://link-sfera`; до него Sfera честно показывает «не связан».

## 4. Приложения, магазины и релизы

**Каждый продукт — отдельное приложение.** Не «Vault с режимом соцсети»:
разные package id, разные листинги, разные подписи, разные циклы ревью.

| | Vault (мессенджер) | Sfera (соцсеть) |
|---|---|---|
| Package / bundle id | `com.vault.vault` | `com.vault.sfera` |
| Desktop | Tauri, `vault-desktop/` | Tauri, `sfera/src-tauri/` |
| Android | APK/AAB из `vault-desktop/src` | APK/AAB из `sfera/src` |
| Версия | `vault-desktop/src-tauri/tauri.conf.json` | `sfera/src-tauri/tauri.conf.json` |
| Тег | `vX.Y.Z` | `sfera-vX.Y.Z` |
| Артефакты | `/home/maksim/vault-releases/<версия>/` | `/home/maksim/vault-releases/sfera/<версия>/` |
| Подпись Android | свой keystore | **свой** keystore (не переиспользовать) |

Правила релиза:

1. **Один магазин — один листинг на продукт.** Магазины не любят «два
   приложения в одном»; пользователь ставит то, что ему нужно.
2. **Общий keystore запрещён.** Компрометация одного приложения не должна
   позволять обновлять второе. Ключи — в `~/.hermes/secrets` (вне git).
3. **Версии не синхронизируются искусственно.** Общая версия нужна только
   `vault-core`; у приложений свои.
4. **Тег — на коммит, а не на «хвост».** Проверка `release-tag-check.mjs`
   расширяется на префикс `sfera-`.
5. **Изменение `vault-core` требует зелёных обоих приложений.** Гейт
   `kernel-consumers` в CI уже это делает; при split он станет двумя
   пайплайнами с общим артефактом ядра.

## 5. Целевые репозитории и порядок переноса

```
vault/                       # самостоятельный мессенджер + его CLI и relay
vault-sfera/                 # соцсеть, зависимая от публичных портов мессенджера
vault-video/                 # будущий видеохостинг/стриминг, при появлении
vault-contracts/             # только если общий контракт действительно нужен
                             # отдельной версионируемой библиотекой
```

Текущий `whisper/` — исходный репозиторий миграции, не новая обязательная
структура навсегда. До переключения remote его статус не выдаётся за завершённый
split. Перенос делается отдельным этапом:

1. Проверить, что Sfera не импортирует прикладной код мессенджера; составить
   список фактических общих зависимостей.
2. Извлечь историю `sfera/` (`git filter-repo` либо subtree split), не копировать
   только рабочий каталог.
3. Создать `vault-sfera`, перенести workspace, CI, документы и релизный процесс.
4. Общие зависимости подключить как версионируемые пакеты; случайные
   `../vault-*` запрещены гейтом.
5. Прогнать Sfera отдельно, мессенджер без каталога Sfera и контрактные тесты
   совместимости. После этого пометить исходное расположение перенесённым.

Будущие приложения получают собственный репозиторий при создании, а не
дожидаются роста monorepo.

---

## 6. Что делаем прямо сейчас

- Независимые проверки продуктов: Sfera (контракты, workspace, оболочка Tauri)
  не заменяет проверки мессенджера и не требует его изменения.
- Перенос `sfera/` в `vault-sfera` с сохранением истории — отдельная задача
  миграции, не смешивается с изменением протокола комментариев.
- Релизный документ Sfera: `sfera/RELEASE.md` (десктоп, Android, теги,
  артефакты, листинги); после split — в его репозитории.
- Скрипт сборки десктопа: `sfera/scripts/build-desktop.sh`.
- Гейт отсутствия прикладных импортов между репозиториями и отсутствия
  скрытых path-зависимостей на соседний продукт.
