# ADR-008: Монетизация Sfera

**Дата**: 21.11.2026
**Статус**: принято (решение PM)
**Основание**: указание владельца 21.11.2026 — платными могут быть только
место на диске для медиа и релей; рассмотреть коммерческие страницы, не ломая
распределённую архитектуру.
**Связанные документы**: ADR-006 (архитектура Sfera), ADR-007 (приложения и
магазины), `docs/design/feature-service-map.md`.

---

## 1. Решение в одном абзаце

Sfera остаётся бесплатной социальной сетью: лента, сферы, контакты, посты и
коммерческие страницы **не продаются**. Платить можно только за **ресурсы**:
место под медиа в хранилище Vault и приоритет/объём доставки через релей.
Коммерческая страница — это тип аккаунта, а не платная функция; она платит
ровно за то, что потребляет (гигабайты и доставку), а не за видимость.
Рекламы, продажи охвата, алгоритмической выдачи и торговли контактами нет —
это не «пока не делаем», а запрещено архитектурой.

---

## 2. Что можно продавать (и почему только это)

| Платно | Что это | Почему допустимо |
|---|---|---|
| Место под медиа | Квота в хранилище Vault (`storage-vault`), альтернатива своему диску | Реальный расход ресурса; пользователь может не платить и хранить у себя |
| Релей | Приоритет доставки и повышенный объём для больших аудиторий | Реальный расход сервера; бесплатный режим остаётся best-effort |

| Бесплатно | Почему |
|---|---|
| Лента, посты, сферы, контакты | Ядро продукта; иначе сеть не растёт |
| Коммерческая страница | Монетизируется её потребление, а не факт существования |
| Верификация страницы | Доверие нельзя продавать: платная галочка — это ложь |
| История, ключи, экспорт | Данные пользователя принадлежат ему |

**Запрещено архитектурой:** рекламный аукцион, продажа охвата («покажем пост
больше»), алгоритмическая лента, продажа графа контактов, платное удаление
рекламы, скрытый сбор аналитики. Центральной ленты не существует: агрегация
локальная (ADR-006 §1), поэтому «продать место в ленте» технически нечего.

---

## 3. Коммерческие страницы

**Модель.** Коммерческая страница — это `AccountKind::Organization` (ADR-006
§17) с публичной видимостью. Не второй тип ленты и не отдельная подсистема:
тот же аккаунт, ключ, сертификат, репозиторий и права.

**Видимость.** Два режима:

1. **Закрытая страница** — аудитория из сфер, как обычный аккаунт.
2. **Публичная страница** — контент явно публичный. Он подписан автором, но
   **не является конфиденциальным**: ключ страницы доступен подписчикам,
   контент может быть перепубликован. Это честно написано в интерфейсе.
   Приватные сферы и личные посты остаются E2E; публичная страница — осознанный
   выбор владельца, а не утечка.

**Роли.** `Owner`/`Admin`/`Editor`/`Viewer` раскладываются в существующие
`Role` + `RoleOverrides` (`social-rights`); второй модели доступа нет.

**Что продаётся странице.** Ничего «за создание». Планы ресурсов:

- **Storage** — сколько гигабайт медиа лежит в хранилище Vault;
- **Relay** — приоритет и суточный объём доставки для большой аудитории.

Страница без плана работает на бесплатном режиме: своё хранилище + обычный
релей. Это позволяет малому бизнесу присутствовать без платежа, а платить
только при росте медиа/аудитории.

---

## 4. Техническая форма

1. **Цены и лимиты — только с сервера.** Витрина приходит из
   `GET /relay/plans` (как в мессенджере), валидируется в `sfera-billing`;
   UI показывает готовые DTO. Ни одной цены и формулы в JS.
2. **Права на ресурсы — `Entitlement`.** Сервер отдаёт
   `{ storage_bytes, relay_priority, max_fanout, valid_until }`. Клиент не
   повышает лимит сам: значение проверяется на сервере при каждом платеже и
   при выдаче токена релея.
3. **Принуждение — в Rust-портах.** Квота хранилища проверяется в
   `BlobStore`/`storage-vault`, объём доставки — в `Quota` и
   `social-transport`. UI только показывает состояние; обойти лимит из
   фронтенда нельзя, потому что фронтенд не считает.
4. **Платёж — существующий канал.** ЮKassa/релей, как у мессенджера;
   отдельного биллинга в Sfera нет. Чек и возврат — та же процедура.
5. **Офлайн и отказ сервера.** Без сервера планы не выдумываются: страница
   работает на бесплатных лимитах, интерфейс показывает «тариф недоступен»,
   а не «бесплатно навсегда».

---

## 5. Порядок ввода

| Этап | Что | Условие старта |
|---|---|---|
| 0 | Всё бесплатно, своё хранилище | Текущий MVP |
| 1 | Платное хранилище Vault | Появился `storage-vault` и спрос на медиа |
| 2 | Платный релей (приоритет/объём) | Большие аудитории упираются в лимит |
| 3 | Планы для коммерческих страниц | Страницы уже используются бесплатно |

Начинать с платежей нельзя: пока нет продукта и пользователей, платить не за
что. Порядок совпадает с ADR-006 §17: сначала интерфейс и логика, затем
ресурсы.

---

## 6. Метрики, которые не противоречат приватности

Считаем только на устройстве владельца страницы и только то, что нужно для
работы: число подписчиков, объём медиа, число доставок за период. Никакой
третьей стороны, пикселей и «тепловых карт». Сервер видит только факт
доставки и оплаты, но не содержимое и не граф контактов.
