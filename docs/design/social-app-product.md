# Vault Social — продукт и интерфейс

**Дата**: 19.11.2026
**Статус**: предложение к ревью (вместе с ADR-006)
**Аудитория документа**: дизайн, фронтенд, PM; архитектурные решения — в
`adr-006-social-app-architecture.md`.

---

## 1. Позиционирование

**Одна фраза.** «Лента для своих: фото и видео в вашем облаке, видят только те,
кого вы выбрали».

**Чем отличается от привычных соцсетей.**

| Привычно | У нас |
|---|---|
| Профиль на платформе | Профиль = ваш почтовый адрес и ключ; платформы нет |
| «Добавить в друзья» | Контакт из мессенджера; ключ уже есть |
| Публикация «для всех» | Явная аудитория: контакты, круг, выбранные |
| Медиа на сервере соцсети | Медиа в вашем хранилище (диск, WebDAV, S3, Яндекс, Google) |
| Алгоритм и реклама | Хронология, без рекомендаций и рекламы |
| Лайки как рейтинг | Реакции как жест; публичных счётчиков нет |
| «Забанили аккаунт — потеряли всё» | Контакты, лента и файлы остаются у людей |

**Кому это нужно в первую очередь.** Семьи и близкие друзья (5–50 человек),
небольшие сообщества (кружок, школа, двор, клуб), люди, которым важно не
отдавать детские фото и личные видео корпорации. Не «инфлюенсеры» и не
публичные бренды — для них есть Telegram и Instagram.

### 1.1 Имя

Официально — **Vault Social** (магазины, документы, юридические тексты).
Короткое имя — обсуждается; критерии: 1–2 слога, легко в русском и английском,
без ассоциации «VS» (VS Code, versus), не пересекается с известным брендом.

| Кандидат | Плюсы | Минусы |
|---|---|---|
| **Круг** | ровно модель, один слог, по-русски | общее слово; в EN «Krug» непривычно |
| **Свои** | эмоция «для своих», два слога | только RU; трудно защитить как бренд |
| **Vela** | легко в обоих языках, нейтрально | нет смысла; нужна проверка ТМ |
| **Sfera** | круг/сфера, понятно | общее слово, много брендов |

Рекомендация: официально **Vault Social**, коротко **«Круг»** для RU-запуска;
английский бренд выбрать перед международным релизом, когда будет понятен
рынок. В интерфейсе до решения — «Vault Social».

---

## 2. Словарь

- **Пост** — текст + медиа, опубликованный для аудитории.
- **Круг** — именованный набор контактов («Семья», «Работа», «Клуб»).
- **Аудитория** — то, кто увидит конкретный пост: все контакты, круг, выбранные.
- **Хранилище** — где лежат зашифрованные файлы: устройство, WebDAV, S3,
  Яндекс Диск, Google Drive, позже Vault Storage.
- **Локация** — конкретная ссылка на блоб у провайдера.
- **Связанное устройство** — второй телефон/десктоп с сертификатом от
  основного аккаунта.

## 3. Экраны (mobile-first)

Нижняя навигация: **Лента · Круги · (+) · Хранилище · Профиль**.
Десктоп: левая навигация, центр — лента, правая колонка — детали.

### 3.1 Лента

```
┌─────────────────────────────────┐
│ Vault Social        ⟳ синхрон.  │
│ [Все] [Семья] [Клуб] [Избранное]│
├─────────────────────────────────┤
│ ◯ Аня · 2 ч · Круг «Семья»      │
│ Вчера на даче…                  │
│ ┌───────┬───────┐               │
│ │ фото  │ фото  │               │
│ └───────┴───────┘               │
│ [нрав] 3   [ответ]              │
├─────────────────────────────────┤
│ ◯ Паша · 5 ч · Все контакты     │
│ Видео: 0:42                     │
│ ┌─────────────────────────────┐ │
│ │ ▶ постер (миниатюра)        │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

- Хронология, без «рекомендованного».
- Чипы фильтров — круги пользователя + «Все» + «Избранное».
- Плашка синхронизации: «обновлено 12:40», «нет сети — показаны сохранённые».
- Медиа: миниатюры сразу, полный файл — по тапу; видео — постер и Range.
- Если медиа недоступно: «Файл недоступен: хранилище не отвечает» + «Повторить».

**Пустое состояние**: «Пока тихо. Добавьте контакты в мессенджере или создайте
круг — и пригласите своих».

### 3.2 Круги

```
┌─────────────────────────────────┐
│ Круги                    [+ new]│
├─────────────────────────────────┤
│ Семья                6 человек >│
│ Работа               4 человека >│
│ Клуб                 12 человек>│
├─────────────────────────────────┤
│ Кто видит мои посты по умолчанию│
│ (•) Все контакты  ( ) Круг…     │
└─────────────────────────────────┘
```

- Внутри круга: список контактов, «добавить из контактов», «убрать».
- У контакта видно: есть ли ключ (иначе «не сможет получать»), последняя
  активность (если разрешена), «заблокировать».
- Удаление из круга не удаляет историю у человека — предупреждение честное.

### 3.3 Создание поста

```
┌─────────────────────────────────┐
│ Новый пост               [X]    │
│ ┌─────────────────────────────┐ │
│ │ Что нового?                 │ │
│ └─────────────────────────────┘ │
│ [фото] [видео] [файл]           │
│ ┌───────┬───────┐               │
│ │ превью│ +     │               │
│ └───────┴───────┘               │
│ Кто увидит:                     │
│ [Семья ×] [Клуб ×] [+ круг]     │
│ ⓘ 6 человек получат пост        │
│                                 │
│ [Опубликовать]                  │
└─────────────────────────────────┘
```

- Аудитория выбирается **до** публикации и всегда видна.
- Прогресс честный: «шифрую… → загружаю в WebDAV… → отправляю 4 из 6».
- Офлайн: «Сохранить и отправить позже» (outbox).
- Черновик сохраняется автоматически.
- Публикация «всем контактам» — это явный выбор, не дефолт по умолчанию для
  нового пользователя (дефолт — пусто, пока не выбран круг).

### 3.4 Просмотр поста

- Полноэкранный просмотрщик: свайп, зум, видео с перемоткой.
- Подпись автора, время, аудитория (только для автора: «видели: 6»).
- Действия: реакция, ответить в 1:1, «пожаловаться», «скрыть автора».
- Для автора: «кто видел» (если получатели подтвердили), «удалить у себя»,
  «удалить у всех» (честно: удалит у тех, кто получит команду; копии могут
  остаться).

### 3.5 Хранилище

```
┌─────────────────────────────────┐
│ Хранилище               [+ add] │
├─────────────────────────────────┤
│ ● WebDAV · nextcloud.local      │
│   12,4 ГБ из 50 · здорово       │
│ ● Яндекс Диск                   │
│   3,1 ГБ · требуется вход       │
│ ○ Vault Storage                 │
│   скоро · займёт своё место     │
├─────────────────────────────────┤
│ По умолчанию: WebDAV            │
│ [Перенести медиа]               │
└─────────────────────────────────┘
```

- Мастер подключения как в почте: список пресетов (Устройство, Nextcloud,
  Generic WebDAV, Selectel, VK Cloud, MinIO, Яндекс Диск) — поля уже
  заполнены; «Другое» — URL, логин, пароль/токен, bucket, регион вручную.
  Яндекс/Google — только кнопка OAuth. Google Drive — позже, механизм тот же.
- Проверка сразу: «записать тестовый файл — успешно, ссылка доступна».
- «Требуется вход» — токен истёк; повторный вход, файлы не теряются.
- «Перенести медиа» — копирование блобов и добавление локаций; старые ссылки
  остаются живыми, пока пользователь не удалит источник.

### 3.6 Профиль

- Имя, аватар, био, ссылки (опционально).
- Стена — собственные посты (личный канал).
- Отпечаток ключа + QR для сверки контакта.
- Связанные устройства: список, «отозвать».
- Приватность: кто видит профиль, кто может писать, кто видит «видел».
- Экспорт: «забрать свои данные» (репозиторий + манифест).

### 3.7 Первый запуск

1. «Vault Social — лента для своих». Кратко: где хранятся файлы и кто их видит.
2. Вход: тот же аккаунт, что в Vault (или «у меня ещё нет Vault» → установка
   мессенджера). Если социальный раздел внутри приложения — шага нет.
3. Хранилище: «Где хранить фото?» — «На этом устройстве» (по умолчанию),
   «Подключить облако» (мастер).
4. Круг: «Соберите первый круг» — выбрать из контактов; можно пропустить.
5. Готово: пустая лента + подсказка «Опубликуйте первый пост для круга».

## 4. Ключевые потоки

### 4.1 Публикация с медиа

1. Пользователь выбирает фото/видео.
2. Rust: читает файл, генерирует `file_key`, шифрует чанками, считает `blob_id`.
3. Rust: `BlobStore.put` в выбранный провайдер, получает локацию; делает
   миниатюру и кладёт её отдельным блобом.
4. Rust: собирает `social_post` (манифест + ключи), подписывает, кладёт в outbox.
5. Rust: отправляет конверты получателям (email/релей), обновляет состояние.
6. UI: показывает прогресс по шагам и итог «Опубликовано · 6 человек».

Ошибка на шаге 3: пост остаётся черновиком с понятной причиной («провайдер
отклонил файл: нет места»); на шаге 5 — «медиа загружено, пост ждёт отправки».

### 4.2 Просмотр чужого поста

1. Конверт получен и расшифрован; манифест в локальной БД.
2. Лента показывает миниатюру из кэша или тянет её по локации.
3. Тап по видео: Range-запрос к провайдеру, расшифровка чанков на лету.
4. Провайдер недоступен: «Файл временно недоступен» + «Повторить»; текст поста
   остаётся видимым.

### 4.3 Подключение хранилища (пресет или вручную)

1. «Хранилище» → «Добавить» → выбрать пресет (например, «Selectel S3») или
   «Другое».
2. Поля уже заполнены (endpoint, регион, шаблон bucket); пользователь вводит
   только логин/ключи или правит адрес.
3. Для OAuth-провайдера — окно входа и возврат в приложение.
4. Rust проверяет: создать тестовый блоб, получить ссылку, прочитать диапазон.
5. «Готово»: провайдер в списке, можно сделать основным.

### 4.4 Удаление контакта из круга

1. «Круги» → круг → контакт → «Убрать».
2. Предупреждение: «Он больше не будет получать новые посты. Старые копии
   останутся у него».
3. Rust: новая эпоха ключа аудитории; новые посты шифруются новым ключом;
   участнику уходит уведомление об изменении состава (если он в контактах).

## 5. Состояния и ошибки (обязательные)

| Состояние | Что видит пользователь |
|---|---|
| Нет сети | «Нет сети. Лента из сохранённых; новые посты уйдут позже» |
| Хранилище недоступно | «WebDAV не отвечает. Медиа не загрузится, текст можно опубликовать» |
| Токен истёк | «Нужно снова войти в Яндекс Диск» + кнопка |
| Мало места | «На Яндекс Диске осталось 0,3 ГБ. Выберите другое хранилище» |
| Ключ контакта неизвестен | «У контакта нет ключа — он не получит пост» |
| Пост не дошёл до части | «Доставлено 5 из 6. Повторить» |
| Файл повреждён | «Файл не расшифровывается. Запросить заново у автора» |
| Жалоба | «Жалоба отправлена оператору» (как в мессенджере) |

## 6. Чего сознательно НЕ делаем

- Алгоритмическая лента, рекомендации, «популярное».
- Публичные счётчики подписчиков и лайков как рейтинг.
- Реклама и аналитические SDK.
- Публичные профили, доступные без контакта.
- Автоматическое скачивание всего медиа (только по требованию).
- Сканирование контента на сервере (E2E).
- Терминальный клиент.

## 7. Метрики продукта (не тщеславия)

- **Активация**: доля новых, кто собрал круг и опубликовал первый пост.
- **Доставка**: доля постов, дошедших до всех получателей.
- **Медиа**: время до миниатюры; доля видео, начавших играть < 2 с.
- **Хранилище**: доля успешных операций по провайдеру; сколько пользователей
  подключили облако vs остались на устройстве.
- **Приватность**: ноль инцидентов «пост увидел не тот» (тест на пересечение
  аудиторий), ноль ключей в логах.
- **Удержание**: недельная активность круга (не отдельного человека).

## 8. Открытые вопросы к дизайну

1. Один экран «Лента» или две вкладки «Лента» и «Стена»? Предложение: лента
   общая, стена — внутри профиля.
2. Реакции: набор из 5 или свободные эмодзи? Предложение: 5, без счётчика.
3. Комментарии в MVP? Предложение: нет, «ответить в чат» + реакции.
4. Как показывать «кто видел»: по умолчанию выключено (приватность).
5. Тёмная тема: наследуем токены мессенджера, отдельного дизайна не делаем.
6. Языки: ru/en/zh, как в мессенджере; тексты — в локалях, не в компонентах.
