# Vault Sfera — продукт и интерфейс

**Дата**: 19.11.2026
**Статус**: предложение к ревью (вместе с ADR-006)
**Аудитория документа**: дизайн, фронтенд, PM; архитектурные решения — в
`adr-006-social-app-architecture.md`.

---

## 1. Позиционирование

**Одна фраза.** «Лента для своих: фото и видео в вашем облаке, видят только те,
кого вы выбрали».

**Чем отличается от привычных соцсетей.**

| Привычно | У нас |
|---|---|
| Профиль на платформе | Профиль = **fingerprint публичного ключа**; платформы нет, email — только адрес доставки |
| «Добавить в друзья» | Контакт из мессенджера; ключ уже есть |
| Публикация «для всех» | Явная аудитория: контакты, сфера, выбранные |
| Медиа на сервере соцсети | Медиа в вашем хранилище (диск, WebDAV, S3, Яндекс, Google) |
| Алгоритм и реклама | Хронология, без рекомендаций и рекламы |
| Лайки как рейтинг | Реакции как жест; публичных счётчиков нет |
| «Забанили аккаунт — потеряли всё» | Контакты, лента и файлы остаются у людей |

**Кому это нужно в первую очередь.** Семьи и близкие друзья (5–50 человек),
небольшие сообщества (клуб, школа, двор, сообщество), люди, которым важно не
отдавать детские фото и личные видео корпорации. Не «инфлюенсеры» и не
публичные бренды — для них есть Telegram и Instagram.

### 1.1 Имя и бренд

Официально — **Vault Sfera** (магазины, документы, юридические тексты).
Короткое имя — **Sfera**: два слога, одинаково произносится по-русски и
по-английски, нейтральна и масштабируется на международный релиз.

- **Логотип** — **VS** (решение владельца 19.11.2026).
- **Цвета**: фиолетовый (основной) и золотой (акцент) — свои токены Sfera; у
  мессенджера палитра другая, код и бренд раздельны.
- в листинге магазина — «Vault Sfera»;
- на иконке и в лаунчере — логотип «VS»;
- в интерфейсе — «Sfera».

Наборы контактов называются **сферами** («Сфера „Семья“»), а не «кругами»:
слово «круг» уже занято в мессенджере («Мой круг»), и два разных смысла
в одном бренде путают людей. «Свои» тоже не используем — плохо звучит
по-английски. Проверку ТМ по классам 9/38/42 сделать до подачи в магазины.

## 2. Словарь

**Идентичность — fingerprint, не email.** ID пользователя = короткий
отпечаток публичного ключа в форме `xx:…:****` (первые 8 байт), то же правило,
что в мессенджере: данные живут под fp-namespace (`fp:` — префикс записи, не
часть отпечатка), отпечаток стабилен при смене почты и решает, кто это
(`vault-core/identity.rs::fingerprint_from_public_key`). Email — **только адрес доставки** конверта
и способ найти собеседника при первом контакте; он не identity и не ключ
таблиц. Смена ящика не меняет пользователя; один fp может иметь несколько
адресов и алиасов. Заявка, контакт, сфера, пост и права привязаны к **fp**.

- **Пост** — текст + медиа, опубликованный для аудитории.
- **Заявка** — запрос нового пользователя на доступ к странице. Владелец
  добавляет, отклоняет или блокирует; без его решения доступа нет.
- **Контакт** — принятая заявка; взаимный доступ к контенту «для всех
  контактов».
- **Роль** — пресет прав для контакта: Близкий, Друг, Знакомый, Ограниченный.
- **Права** — что контакт может делать: смотреть, реагировать, видеть медиа,
  историю, профиль.
- **История** — прошлые посты, которые новый контакт увидит при добавлении.
- **Сфера** — именованный набор контактов («Семья», «Работа», «Клуб»).
- **Аудитория** — то, кто увидит конкретный пост: все контакты, сфера,
  выбранные, все кроме.
- **Хранилище** — где лежат зашифрованные файлы: устройство, WebDAV, S3,
  Яндекс Диск, Google Drive, позже Vault Storage.
- **Локация** — конкретная ссылка на блоб у провайдера.
- **Связанное устройство** — второй телефон/десктоп с сертификатом от
  основного аккаунта.

## 3. Экраны (mobile-first)

Нижняя навигация: **Лента · Контакты · (+) · Хранилище · Профиль**.
Десктоп: левая навигация, центр — лента, правая колонка — детали.

### 3.1 Лента

```
┌─────────────────────────────────┐
│ Sfera               ⟳ синхрон.  │
│ [Все] [Семья] [Клуб] [Избранное]│
├─────────────────────────────────┤
│ ◯ Аня · 2 ч · Сфера «Семья»     │
│ Вчера на даче…                  │
│ ┌───────┬───────┐               │
│ │ фото  │ фото  │               │
│ └───────┴───────┘               │
│ [нрав] 3   [ответ]              │
├─────────────────────────────────┤
│ ◯ Паша · 5 ч · Все контакты     │
│ Видео: 0:42                     │
│ ┌─────────────────────────────┐ │
│ │ ▶ постер (миниатюра)        │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

- Хронология, без «рекомендованного».
- Чипы фильтров — сферы пользователя + «Все» + «Избранное».
- Плашка синхронизации: «обновлено 12:40», «нет сети — показаны сохранённые».
- Медиа: миниатюры сразу, полный файл — по тапу; видео — постер и Range.
- Если медиа недоступно: «Файл недоступен: хранилище не отвечает» + «Повторить».

**Пустое состояние**: «Пока тихо. Добавьте контакты в мессенджере или создайте
сферу — и пригласите своих».

### 3.2 Контакты и сферы

```
┌─────────────────────────────────┐
│ Контакты                 [+ add]│
│ Заявки (3)                      │
│ ┌─────────────────────────────┐ │
│ │ ◯ Игорь · общий контакт: Аня│ │
│ │ «Привет! Хочу читать вас»   │ │
│ │ [Добавить] [Отклонить]      │ │
│ └─────────────────────────────┘ │
├─────────────────────────────────┤
│ Семья                6 человек >│
│ Работа               4 человека >│
│ Клуб                 12 человек>│
├─────────────────────────────────┤
│ Контакты (24)                   │
│ ◯ Аня        Близкий  Семья,Клуб│
│ ◯ Паша       Друг     Работа    │
│ ◯ Олег       Огранич. —         │
└─────────────────────────────────┘
```

- **Заявки** — входящие запросы. В карточке: профиль, общие контакты,
  сообщение, дата. «Добавить» открывает выбор роли, сфер и истории;
  «Отклонить» закрывает заявку; «Заблокировать» — навсегда.
- **Контакт** — роль, сферы, права, «показать историю», «убрать», «заблокировать».
- **Сферы** — та же вкладка, секция ниже: состав, «добавить из контактов»,
  «убрать». Удаление из сферы не удаляет историю у человека — предупреждение
  честное.
- **Добавить контакт**: QR/ссылка-приглашение с **fingerprint**, из контактов
  мессенджера. Email — только подсказка для доставки приглашения, не ID;
  добавленный контакт идентифицируется по fp из подписанного bundle.
- **Кто может отправлять заявки** — в настройках приватности: по ссылке
  (по умолчанию), все, никто.

### 3.3 Создание поста

```
┌─────────────────────────────────┐
│ Новый пост               [X]    │
│ ┌─────────────────────────────┐ │
│ │ Что нового?                 │ │
│ └─────────────────────────────┘ │
│ [фото] [видео] [файл]           │
│ ┌───────┬───────┐               │
│ │ превью│ +     │               │
│ └───────┴───────┘               │
│ Кто увидит:                     │
│ [Семья ×] [Клуб ×] [+ сфера]    │
│ ⓘ 6 человек получат пост        │
│                                 │
│ [Опубликовать]                  │
└─────────────────────────────────┘
```

- Аудитория выбирается **до** публикации и всегда видна.
- Прогресс честный: «шифрую… → загружаю в WebDAV… → отправляю 4 из 6».
- Офлайн: «Сохранить и отправить позже» (outbox).
- Черновик сохраняется автоматически.
- Публикация «всем контактам» — это явный выбор, не дефолт по умолчанию для
  нового пользователя (дефолт — пусто, пока не выбрана сфера).

### 3.4 Просмотр поста

- Полноэкранный просмотрщик: свайп, зум, видео с перемоткой.
- Подпись автора, время, аудитория (только для автора: «видели: 6»).
- Действия: реакция, ответить в 1:1, «пожаловаться», «скрыть автора».
- Для автора: «кто видел» (если получатели подтвердили), «удалить у себя»,
  «удалить у всех» (честно: удалит у тех, кто получит команду; копии могут
  остаться).

### 3.5 Хранилище

```
┌─────────────────────────────────┐
│ Хранилище               [+ add] │
├─────────────────────────────────┤
│ ● WebDAV · nextcloud.local      │
│   12,4 ГБ из 50 · здорово       │
│ ● Яндекс Диск                   │
│   3,1 ГБ · требуется вход       │
│ ○ Vault Storage                 │
│   скоро · займёт своё место     │
├─────────────────────────────────┤
│ По умолчанию: WebDAV            │
│ [Перенести медиа]               │
└─────────────────────────────────┘
```

- Мастер подключения как в почте: список пресетов (Устройство, Nextcloud,
  Generic WebDAV, Selectel, VK Cloud, MinIO, Яндекс Диск) — поля уже
  заполнены; «Другое» — URL, логин, пароль/токен, bucket, регион вручную.
  Яндекс/Google — только кнопка OAuth. Google Drive — позже, механизм тот же.
- Проверка сразу: «записать тестовый файл — успешно, ссылка доступна».
- «Требуется вход» — токен истёк; повторный вход, файлы не теряются.
- «Перенести медиа» — копирование блобов и добавление локаций; старые ссылки
  остаются живыми, пока пользователь не удалит источник.

### 3.6 Профиль

- Имя, аватар, био, ссылки (опционально).
- Стена — собственные посты (личный канал).
- Отпечаток ключа + QR для сверки контакта.
- Связанные устройства: список, «отозвать».
- Приватность: кто видит профиль, кто может писать, кто видит «видел».
- Экспорт: «забрать свои данные» (репозиторий + манифест).

### 3.7 Первый запуск

1. «Vault Sfera — лента для своих». Кратко: где хранятся файлы и кто их видит.
2. Вход: «Связать с Vault» (QR/файл) — один аккаунт, контакты и сферы;
   или «Начать с нуля» — новый ключ и ящик. Копии приватного ключа нет:
   Sfera получает сертификат устройства.
3. Хранилище: «Где хранить фото?» — «На этом устройстве» (по умолчанию),
   «Подключить облако» (мастер).
4. Контакты: «Примите заявки или соберите первую сферу» — выбрать из контактов
   мессенджера; можно пропустить.
5. Готово: пустая лента + подсказка «Опубликуйте первый пост для сферы».

### 3.8 Десктоп

Десктоп — обязательная версия с тем же набором возможностей, а не «посмотреть
ленту». Отличия только в раскладке и системной интеграции:

```
┌──────────┬──────────────────────────────┬───────────────┐
│ Sfera    │ Лента                        │ Пост / детали │
│ Лента    │ [Все] [Семья] [Клуб]         │ ◯ Аня         │
│ Сферы    │ ┌──────────────────────────┐ │ фото 1 из 3   │
│ Хранилище│ │ пост + медиа             │ │ Кто видит:    │
│ Профиль  │ └──────────────────────────┘ │ Сфера «Семья» │
│          │ ...                          │ [ответ] [жал] │
└──────────┴──────────────────────────────┴───────────────┘
```

- Левая навигация, центральная лента, правая колонка деталей; минимум
  1024×700.
- Drag-and-drop файлов в композер, вставка из буфера, мультивыбор, горячие
  клавиши (j/k, space, Esc).
- Локальная папка как полноценное хранилище (нативный путь), плюс WebDAV/S3.
- Трей со статусом синхронизации и нативные уведомления.
- Сборка: Windows/Linux/macOS и Android из одного Tauri-shell; приёмка — на
  обеих платформах, фича без десктопа не считается готовой.
- Терминального клиента нет.

### 3.9 Права контакта

```
┌─────────────────────────────────┐
│ Аня                       [×]   │
│ Роль: [Близкий ▾]               │
│ Сферы: [Семья ×] [Клуб ×] [+]   │
│ Права:                          │
│ [x] видит посты для всех        │
│ [x] видит медиа                 │
│ [x] может реагировать           │
│ [ ] видит прошлые посты         │
│ [x] видит профиль               │
│ [ ] может писать первым         │
│ [Убрать из контактов]  [Блок]   │
└─────────────────────────────────┘
```

- Роль задаёт пресет; переключатели — точечные исключения.
- «Видит медиа» выключен → ключи медиа не выдаются, файл не скачивается.
- Изменения применяются к новым постам; старые копии не отзываются — пишем
  это прямо.
- При одобрении заявки тот же экран: роль, сферы, история и предпросмотр
  «Аня увидит 42 поста».

## 4. Ключевые потоки

### 4.1 Публикация с медиа

1. Пользователь выбирает фото/видео.
2. Rust: читает файл, генерирует `file_key`, шифрует чанками, считает `blob_id`.
3. Rust: `BlobStore.put` в выбранный провайдер, получает локацию; делает
   миниатюру и кладёт её отдельным блобом.
4. Rust: собирает `social_post` (манифест + ключи), подписывает, кладёт в outbox.
5. Rust: отправляет конверты получателям (email/релей), обновляет состояние.
6. UI: показывает прогресс по шагам и итог «Опубликовано · 6 человек».

Ошибка на шаге 3: пост остаётся черновиком с понятной причиной («провайдер
отклонил файл: нет места»); на шаге 5 — «медиа загружено, пост ждёт отправки».

### 4.2 Просмотр чужого поста

1. Конверт получен и расшифрован; манифест в локальной БД.
2. Лента показывает миниатюру из кэша или тянет её по локации.
3. Тап по видео: Range-запрос к провайдеру, расшифровка чанков на лету.
4. Провайдер недоступен: «Файл временно недоступен» + «Повторить»; текст поста
   остаётся видимым.

### 4.3 Подключение хранилища (пресет или вручную)

1. «Хранилище» → «Добавить» → выбрать пресет (например, «Selectel S3») или
   «Другое».
2. Поля уже заполнены (endpoint, регион, шаблон bucket); пользователь вводит
   только логин/ключи или правит адрес.
3. Для OAuth-провайдера — окно входа и возврат в приложение.
4. Rust проверяет: создать тестовый блоб, получить ссылку, прочитать диапазон.
5. «Готово»: провайдер в списке, можно сделать основным.

### 4.4 Удаление контакта из сферы

1. «Контакты» → сфера → контакт → «Убрать».
2. Предупреждение: «Он больше не будет получать новые посты. Старые копии
   останутся у него».
3. Rust: новая эпоха ключа аудитории; новые посты шифруются новым ключом;
   участнику уходит уведомление об изменении состава (если он в контактах).

### 4.5 Заявка в контакты

1. Новый пользователь открывает ссылку/QR владельца → «Запросить доступ».
2. Sfera отправляет заявку: **fingerprint**, публичный ключ, профиль, сообщение.
   Заявка подписана ключом заявителя — fp проверяется из подписи, а не из
   email. Если ключ владельца известен — E2E; адрес нужен только чтобы
   доставить конверт (минимальное приглашение без ключа — тоже по fp).
3. Владелец видит заявку; «Добавить» → роль, сферы, история, предпросмотр
   «Аня увидит 42 поста».
4. Устройство владельца выдаёт ключи аудиторий и отправляет accept; заявитель
   видит «Вас добавили: роль Знакомый, сфера Знакомые».
5. «Отклонить» закрывает заявку (можно молча); «Заблокировать» — новые
   заявки не приходят.
6. Если владелец офлайн — заявка ждёт. Сервера, который одобрит её за него,
   нет: это цена serverless-модели.

## 5. Состояния и ошибки (обязательные)

| Состояние | Что видит пользователь |
|---|---|
| Нет сети | «Нет сети. Лента из сохранённых; новые посты уйдут позже» |
| Хранилище недоступно | «WebDAV не отвечает. Медиа не загрузится, текст можно опубликовать» |
| Токен истёк | «Нужно снова войти в Яндекс Диск» + кнопка |
| Мало места | «На Яндекс Диске осталось 0,3 ГБ. Выберите другое хранилище» |
| Ключ контакта неизвестен | «У контакта нет ключа — он не получит пост» |
| Заявка отправлена | «Заявка отправлена. Ждём решения владельца» |
| Заявку отклонили | «Доступ не предоставлен» (без подробностей) |
| Нет доступа к посту | «Этот пост не для вас: вы не в аудитории» |
| Медиа закрыто ролью | «Автор ограничил медиа для вашей роли» |
| Пост не дошёл до части | «Доставлено 5 из 6. Повторить» |
| Файл повреждён | «Файл не расшифровывается. Запросить заново у автора» |
| Жалоба | «Жалоба отправлена оператору» (как в мессенджере) |

## 6. Чего сознательно НЕ делаем

- Алгоритмическая лента, рекомендации, «популярное».
- Публичные счётчики подписчиков и лайков как рейтинг.
- Реклама и аналитические SDK.
- Публичные профили, доступные без контакта.

## 7. Метрики продукта (не тщеславия)

- **Активация**: доля новых, кто собрал сферу и опубликовал первый пост.
- **Доставка**: доля постов, дошедших до всех получателей.
- **Медиа**: время до миниатюры; доля видео, начавших играть < 2 с.
- **Хранилище**: доля успешных операций по провайдеру; сколько пользователей
  подключили облако vs остались на устройстве.
- **Приватность**: ноль инцидентов «пост увидел не тот» (тест на пересечение
  аудиторий), ноль ключей в логах.
- **Удержание**: недельная активность сферы (не отдельного человека).

## 8. Открытые вопросы к дизайну

1. Один экран «Лента» или две вкладки «Лента» и «Стена»? Предложение: лента
   общая, стена — внутри профиля.
2. Реакции: набор из 5 или свободные эмодзи? Предложение: 5, без счётчика.
3. Комментарии в MVP? Предложение: нет, «ответить в чат» + реакции.
4. Как показывать «кто видел»: по умолчанию выключено (приватность).
5. Тёмная тема: свои токены Sfera — фиолетовый и золотой; у мессенджера
   палитра другая, наследовать нечего (код и бренд раздельны).
6. Языки: ru/en/zh, как в мессенджере; тексты — в локалях, не в компонентах.
