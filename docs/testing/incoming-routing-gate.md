# Гейт маршрутизации входящих (`smoke:incoming`, W1 ADR-005)

`vault-desktop/scripts/incoming-routing-smoke.mjs` — входит в `npm run build`
(сразу после `smoke:m0-wire`, до `vite build`).

## Зачем

W1 перенёс **решение** «что это за письмо» из `features/incoming.js` в Rust
(`vault_classify_incoming`), оставив в JS только эффекты. Ошибка в таком обмене
не видна ни сборке, ни `check-template`, ни смоукам других модулей:

| Поломка | Что увидел бы пользователь |
|---|---|
| маршрутизатор не зовёт мост | письма не считаются, уведомлений нет — «тихий» мессенджер |
| профиль обработан как сообщение | в чате пустые сообщения от каждого обновления профиля |
| сигнал звонка обработан как сообщение | звонок не звонит, зато растёт бейдж |
| канал не распознан | посты канала исчезают |
| ошибка моста проглочена как «не наше письмо» | почта теряется молча, без ретрая |

Проверять это живьём на телефоне — дорого и невоспроизводимо. Гейт запускает
**настоящий** маршрутизатор в node, подменив только внешние мосты.

## Как устроен

Как и `groups-load-smoke`, тест не импортирует модуль напрямую (он тянет Tauri,
api, crypto, relay): копия `src/features/incoming.js` пишется в `/tmp` с
переписанными импортами, и в неё подставляются моки. Тестируется настоящий код,
а не его пересказ.

Перед каждым кейсом стенд сбрасывается: счётчики одного кейса не должны
«доказывать» следующий.

## Что проверяется (16 утверждений)

| `kind` от Rust | Ожидаемые эффекты |
|---|---|
| `message` | бейдж вырос, `vault_store_incoming_message` вызван |
| `profile` | `saveProfile` вызван, бейджа нет |
| `call` | `handleCallSignal` вызван, бейджа нет |
| `presence` | только `noteHeartbeat` (без повторного решения о типе) |
| `channel` | бейдж `channel:<id>` вырос (пост канала — сообщение) |
| `group-service` (`hav`) | `replyGroupAvatarHeal` для группы |
| `null` | ничего не происходит |
| мост упал | ничего не считается, `processedUnreadIds` пуст, ошибка в `console.error` |

«Мост упал» — отдельная пара утверждений, потому что разница между «не наше
письмо» (`null`) и «не смогли решить» (`undefined`) — не стилистическая: во
втором случае письмо обязано повториться на следующем поллинге.

## Заодно держит `deps`-контракт (R3)

Маршрутизатор больше не читает компонент как `ctx` (0 ссылок, было 62):
зависимости приходят явным объектом. Стенд собирает его явно, поэтому если
маршрутизатор начнёт читать новое поле, которого нет в контракте, кейс упадёт
(`undefined is not a function`) — а не «просто не сработает» в проде.
`channels` и `groups` передаются геттерами: во время батча ренейм адреса
вызывает `loadGroups`, который ПЕРЕПРИСВАИВАЕТ массив, и снимок показал бы
устаревший список.

## Чего гейт не проверяет

- Реальный Tauri-мост и сериализацию `ClassifyResult` → JSON — это проверяет
  Rust (`cargo test`), живая приёмка — на устройстве.
- Семантику самих эффектов (что именно делает `handleCallSignal`) — у них свои
  смоуки/тесты.
- Тексты уведомлений и UI.

## Самопроверка

Гейт проверялся на подставленных поломках:

1. мок `senderEmail` упрощён (`lower()` без извлечения `<адрес>`) → кейсы
   уходят в чужую ветку; гейт это показал (5 провалов), а не «позеленел».
2. `noteHeartbeat` заменён на `ingestSignal` (повторное решение в JS) → мок
   `ingestSignal` бросает исключение, кейс `presence` краснеет.
3. `bridgeDown` не выставлялся в кейсе «мост упал» → кейс краснел, пока флаг не
   стали передавать явно: гейт не принимает «зелёное по умолчанию».
