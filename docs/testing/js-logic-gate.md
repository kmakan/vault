# Ратчет «JS-логика» (`t_8a422c38`, ADR-005 §6/W0)

Три инструмента одного захода, потому что норма этапа состоит из трёх величин
(ADR-005 §5) и мерить их разными правилами — значит получить три несравнимых
числа:

| файл | роль |
|---|---|
| `vault-desktop/scripts/lib/arch-metrics.mjs` | **единственный** код измерения: детекторы, инвентарь `App.vue`, счёт `ctx` |
| `vault-desktop/scripts/audit-arch.mjs` | отчёт человеку; код выхода 1 на крипто-логику и на провал самопроверки |
| `vault-desktop/scripts/js-logic-ratchet-gate.mjs` | гейт сборки: потолок по трём величинам, только затягивается |

Оба подключены к `npm run build` (`gate:js-logic`, `audit:arch`), потолок —
`vault-desktop/scripts/js-logic-baseline.json`.

## Зачем

До W0 `audit:arch` запускался только вручную и ничего не запрещал: он печатал
отчёт, а `npm run build` оставался зелёным при любой новой логике в JS. Это
не гейт, а журнал наблюдений.

Отдельно пришлось править **измерение**, а не код приложения. 19.10.2026
выяснилось, что `ctx` считался двумя правилами сразу:

| инструмент | правило | число |
|---|---|---|
| `audit:arch` (до W0) | сырой счёт `ctx.<имя>` по **всем** `.js`, включая комментарии | **735** |
| `ctx-ratchet-gate` | `features/*.js` + `api.js`, комментарии вырезаны | **686** |

Обе цифры попали в документы (735 — в ADR-005 §3 и в тело `t_bcb8927a`), и
вопрос «откуда новая ctx?» возникал законно: величины не сходились на 49
ссылок, хотя код не менялся. Никакой новой `ctx` не было — были два правила.

Теперь правило одно и живёт в `arch-metrics.mjs`; `ctx-ratchet-gate` импортирует
его оттуда. Число **686** — эталон, **735** печатается в аудите как справка
(«сырой счёт, включая комментарии и файлы вне зоны гейта») с пояснением, что это
другое правило, а не регресс.

## Что измеряется

1. **`ctx`-ссылки** — `features/*.js` + `api.js`, без комментариев. Это то же
   число, что у `ctx-ratchet-gate`; расхождение запрещено самим устройством
   (один код).
2. **Методы `App.vue` с собственной логикой** — всё, что не является делегатом
   вида `return <модуль>.<фн>(<аргументы>);`. Правило делегата одно на три
   инструмента (`audit:arch`, `appvue-inventory`, ратчет).
3. **Протокольные решения в JS** — вызовы `parseEnvelope/parseEnvelopeSafe/
   buildEnvelope`, `JSON.parse` по конверту/плейнтексту, переходы состояния
   звонка (`callState`/`setCallState` с протокольной константой), арифметика
   TTL/`expireAt`. Считается по файлам и по видам.

## Потолок

`--write` **не может повысить** ни одну величину: если хоть одна выросла, запись
отклоняется с перечислением, что именно выросло. Эталон читается из `git show
HEAD:...` — ослабить молча нельзя, только коммитом на ревью. Рабочая копия
эталона, ослабленная относительно закоммиченной, тоже валит гейт.

## Чего гейт намеренно НЕ проверяет

- **`.vue`-компоненты** — их проверяет `check-template.cjs` (класс E4), а
  протокольные решения по W4 живут в фичах и модуле формата.
- **`JSON.parse` локального хранилища** (`drafts`, `folders`, `profiles`) — это
  UI-персистентность, не протокол. В маркер `envelope-json` попадает только
  разбор, чей аргумент назван как конверт/плейнтекст.
- **UI-состояние** (открыт попап, выбран таб) — ADR-003 §2, к R1–R4 не относится.
- **`newMessageId()`** — генерация id в JS: это формат, но не решение о типе
  конверта; вынос в Rust — отдельный пункт W4, а не регресс этого гейта.

## Самопроверка

Детекторы проверяются **при каждом запуске** (10 пар «заведомо плохо / заведомо
чисто», `selfTest()`): `pbkdf2` ловится, `isCryptoReady` — нет; вызов
`parseEnvelope` ловится, объявление функции — нет; `setCallState('active')`
ловится, ключ локали — нет; `ctx` в комментарии — не связь; делегат — не логика.

Живая проверка «подставленное нарушение валит сборку» — 19.10.2026, по одному
нарушению за раз, с откатом:

```bash
cd vault-desktop
# 1. ctx-ссылка
echo 'ctx.selfCheckProbe;' >> src/features/notes-store.js
node scripts/js-logic-ratchet-gate.mjs                     # → 1
#   ✗ 2 нарушени(й) · всего ctx-ссылок: 686 → 687
#   • features/notes-store.js берёт НОВЫЕ ctx-поля: selfCheckProbe (было 2, стало 3)
git checkout src/features/notes-store.js

# 2. метод с логикой в App.vue
#   внутрь methods{}: selfCheckProbe() { return 1; }
node scripts/js-logic-ratchet-gate.mjs                     # → 1
#   ✗ методов с логикой в App.vue: 198 → 199
git checkout src/App.vue

# 3. разбор конверта в JS
echo 'const probe = parseEnvelope(text);' >> src/features/receipts.js
node scripts/js-logic-ratchet-gate.mjs                     # → 1
#   ✗ всего протокольных решений в JS: 69 → 70
#   • features/receipts.js — envelope-parse 1 → 2 (разбор wire-конверта в JS: ...)
git checkout src/features/receipts.js

node scripts/js-logic-ratchet-gate.mjs                     # → 0 (чистое дерево)
```

Выполнено: 1 / 1 / 1 → 0, тексты совпали.
