# Гейт загрузки фронтенда (`boot-smoke`)

`vault-desktop/scripts/boot-smoke.mjs`, запускается внутри `npm run build`
после `vite build`; отдельно — `npm run smoke:boot`.

## Зачем

18.10.2026 собранный APK 0.1.224 открылся **пустым экраном** на живом телефоне,
при этом `npm run build`, восемь гейтов (template-check, src-integrity,
import-gate, owner-refs, feature-import, ctx-ratchet, ctx-coupling, ctx-cycles)
и 68 смоуков (1699 проверок) были зелёными.

Причина — класс «зелёная сборка, сломанный прод» в секции `<script>` SFC:
идентификатор используется, но не объявлен в этой области видимости. Сборщик
не обязан такое ловить (`computed` — глобальное имя в рантайме браузера),
линтера в проекте нет, а ни один смоук не разворачивает `App.vue` целиком.

Два случая, реально уронивших приложение:

| Коммит | Что сломано | Симптом |
|---|---|---|
| `0948c88` | `import { reactive } from 'vue'`, а в файле уже используются `computed`/`watch` (J.3b) | `ReferenceError: computed is not defined` в `setup` |
| `6cdb79b` | прокси чата используют голый `chatStore.state.*` вместо `this.chatStore.state.*` | `ReferenceError: chatStore is not defined` при чтении прокси |
| `a3e82eb` | тост переведён на `uiStore`, но `setup` читал `this?.showToast` (в `setup` `this` === `undefined`), а `uiStore` не живёт на инстансе | тосты глотаются МОЛЧА: `uiStore.toast` — пустышка, `this.showToast` падает на `this.uiStore.setToastMessage` (`TypeError`) |

В обоих случаях корневой шаблон рендерит `<!---->` — пустое окно, без единого
следа в логах устройства (нативный крэш-маркер не появляется: падает JS).
Третий случай виден иначе: приложение работает, но пропадает обратная связь
(«Сохранено», «Файл слишком большой», «Релей недоступен»), поэтому его поймала
живая приёмка (t_e66389bd, 19.10.2026), а не логи устройства.

## Что проверяет

1. `.vite build` → настоящий `dist/` (тот же, что вшивается в APK и бинарник),
   а не исходники: проверка должна видеть артефакт сборки.
2. `dist/` отдаётся статическим сервером на `127.0.0.1` (без новых зависимостей —
   `node:http`).
3. Открывается любым установленным Chrome/Chromium в headless-режиме
   (`CHROME_PATH` для нестандартного пути).
4. Через CDP (встроенный в Node ≥ 22 `WebSocket`) страница перезагружается с
   заглушкой Tauri-моста (`window.__TAURI_INTERNALS__`), иначе `invoke` падает и
   шум маскирует настоящую ошибку.
5. Итог: в `#app` есть отрендеренное содержимое **и** в консоли/Runtime нет
   `ReferenceError`/`TypeError`. Ошибки первой загрузки (до установки заглушки)
   не считаются.
6. Фаза авто-входа дополнительно проверяет **канал тоста** (регресс `a3e82eb`):
   `uiStore.tr('download')` обязан вернуть перевод (а не сам ключ), а
   `uiStore.toast(...)` (путь фич) и `this.showToast(...)` (путь App.vue) —
   довести текст до `.app-toast`. Проверка поведенческая: подменять
   `uiStore`/`showToast` не нужно, тест жмёт те же входы, что и прод.

Выход: `0` — чисто; `1` — пустой корень либо ошибка загрузки (с текстом ошибки и
номером строки в бандле); если браузера нет — громкое `⚠ ПРОПУЩЕНА` и `0`
(нельзя валить сборку там, где Chrome не установлен).

## Самопроверка гейта (обязательна при правках)

Возврат любой из поломок в `src/App.vue` → `npm run build` красный:

```
✗ boot-smoke: приложение не загрузилось (4 проблем)
  корень #app пуст (children=0, len=7) — приложение не отрендерилось
  CONSOLE[error] [vue] render/error: ReferenceError: computed is not defined
```

Для тоста (проверено 19.10.2026: регистрация `setT((k) => k)` +
`setShowToast(() => {})` в `setup`) — три точных сообщения:

```
✗ boot-smoke: приложение не загрузилось (3 проблем)
  uiStore.tr не подключён к i18n (отдаёт сам ключ вместо перевода)
  uiStore.toast(...) не доходит до DOM (.app-toast: «») — тосты фич глотаются
  this.showToast(...) не доходит до DOM (.app-toast: «»)
```

Отдельный флаг `--no-strict` печатает проблемы, но не валит сборку (для отладки).

## Границы

- Гейт ловит падение **при загрузке** и — с 19.10.2026 — канал тоста. Ошибка в
  других обработчиках клика (метод `this.alertMsg`, которого нет) им по-прежнему
  не ловится: нужна статическая проверка `this.*` (открытая задача `t_ddc24f52`).
  Случай тоста — ровно из этого класса (`this.uiStore` на несуществующем
  инстансе), но проверен поведенчески, потому что тост дёшево дёрнуть из CDP.
- Проверяется вход в приложение (экран входа/восстановления), а не весь обход
  экранов: глубже ходят смоуки и живая приёмка на устройстве
  (`docs/testing/recovery-resilience.md`, skill `devops/vault-android-apk`).
- Гейт требует Chrome: он есть на сборочной машине, но это внешняя зависимость.
