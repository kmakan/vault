# Гейт ключей локализации (`locale-keys`)

`vault-desktop/scripts/locale-keys-gate.mjs`, запускается внутри `npm run build`
перед `vite build`; отдельно — `npm run gate:locale-keys`.

## Зачем

В `src/i18n.js` функция `t(key)` возвращает **сам ключ**, если перевода нет:

```js
let s = locales[state.locale]?.[key] || locales.en[key] || key
```

Из-за этого распространённый в проекте приём `t('key') || 'запасной текст'`
не работает так, как задумано: ключ — непустая строка, `||` не срабатывает, и
пользователь видит техническую строку вместо текста.

19.10.2026 это прилетело на живой приёмке вложений (тикет `t_e66389bd`): как
только починили мёртвый канал тостов (`a3e82eb`), тост скачивания показал
`download_complete` — то есть ровно ту строку, которую «прикрывал» фолбэк
`|| \`Сохранено: ${name}\``.

Разбор нашёл **16 таких ключей**, невидимых для всех прежних проверок:

| Проверка | Почему не видит |
|---|---|
| `check-template.cjs` | проверяет bindings шаблона, а не ключи локалей |
| смоуки | подставляют свой `t()` (или не исполняют путь) |
| `vite build` | ключи — обычные строки, сборка их не читает |
| `boot-smoke` | дёргает загрузку и тосты, но не сверяет словари |

## Что проверяет

Каждый **литеральный** аргумент `t('key')` / `tr('key')` в `src/**/*.js|vue`
обязан существовать в `ru.js`, `en.js` и `zh.js`.

Осознанно **не** проверяются:

- динамические ключи — `t('settings_' + cat.id)` (после литерала стоит `+`);
- ключи-переменные — `t(name)`;
- строки-комментарии целиком (`//`, `*`, `/*`) — в пояснениях ключи упоминаются
  как текст, и это не использование (строки не удаляются, а заменяются пустыми,
  чтобы нумерация в сообщениях гейта совпадала с файлом).

## Самопроверка гейта (обязательна при правках)

Удаление `download_complete` из `ru.js` даёт красный с точным адресом:

```
✗ locale-keys: ключей без перевода — 1
  · download_complete — нет в ru (src/features/attachments.js:49)
```

Без этого гейта класс ошибки возвращается молча: `npm run build` зелёный,
а человек в интерфейсе видит `video_unavailable` вместо текста.

## Границы

- Гейт не проверяет **обратную** сторону: ключи в словарях, которые никто не
  использует. Их удаление — ручная гигиена, а не инвариант: часть ключей
  используется динамически (`settings_*`, `dod_*`).
- Динамические ключи остаются вне проверки — их нельзя проверить без
  исполнения кода. Для семейств вида `t('settings_' + cat.id)` инвариант держит
  глаз: список `cat.id` мал и живёт рядом с вызовом.
- Гейт не заменяет `boot-smoke`: он ловит «нет перевода», но не ловит
  «перевод есть, а строка не доходит до экрана» (для тостов это делает
  `docs/testing/boot-gate.md`).
