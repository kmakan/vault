# Стратегия проверок

Как мы проверяем Vault и ПОЧЕМУ проверки устроены именно так. Документ
обязателен для любой новой фичи: он отвечает на вопрос «чем закрывать
изменение», чтобы решение принималось одинаково, а не «как получится».

## Уровни (от дешёвого к дорогому)

| Уровень | Что проверяет | Где | Скорость |
|---|---|---|---|
| Гейты (статика) | структура и ЗАПРЕЩЁННЫЕ состояния | `scripts/*-gate.mjs` | < 5 c |
| Смоуки модулей | поведение фичи | `scripts/*-smoke.mjs` | ~14 c на все |
| Свойства | инварианты на классах входов | `scripts/property-smoke.mjs` | < 1 c |
| Мутации | «а смоук вообще что-то проверяет?» | `scripts/mutation-gate.mjs` | 13 c |
| Живое устройство | сквозной путь на телефоне | `scripts/device-accept.mjs` | 3-5 мин |

Каждый уровень отвечает на СВОЙ вопрос; вместе они закрывают то, что
остальные не видят.

## Что ловит каждый уровень

### Гейты (статика) — «так нельзя делать»

- `ctx-ratchet-gate` — модули не читают компонент (`ctx` = 0).
- `ctx-coupling-gate` / `ctx-cycles-gate` — нет связности и циклов между
  модулями.
- `js-logic-ratchet-gate` — логика не копится в `App.vue`; потолок можно
  только затягивать.
- `options-dup-gate` — в Options API нет дублей ключей; **и** нет коллизий
  МЕЖДУ блоками (`data ∩ computed` перекрывает компьютед → владелец
  недостижим).
- `feature-import-gate` — фича не импортирует фичу (кроме примитивов и
  владельцев).
- `feature-coverage-gate` — у каждой фичи есть смоук; у каждого смоука — набор
  мутаций. Ратчет: ухудшаться нельзя.

### Смоуки — «этот случай работает»

Один смоук — одна фича; проверяем ЧЕРЕЗ публичный API модуля (как его видит
приложение), а не через внутренности.

### Свойства — «это верно для всех входов»

Примеры ловят «этот случай сломался»; свойство ловит «класс поломок».
Утверждения вида «ответ Rust доезжает дословно», «toggle ∘ toggle =
тождество», «счётчик неотрицателен» — на сотнях детерминированно
сгенерированных входов.

**Правило эталона.** Эталон свойства НЕ ДОЛЖЕН совпадать с реализацией:
иначе свойство не отличает «позвали Rust» от «посчитали сами». Для этого
мок Rust-моста возвращает МАРКЕР, а не ту же формулу (см.
`property-smoke.mjs` → expireAt).

### Мутации — «а тест вообще что-то проверяет?»

Подставляем поломку в модуль и требуем, чтобы смоук покраснел. Мутация, на
которой смоук остался зелёным, — это дырка в проверках, которую не найдёт ни
один обычный тест.

**Наборы лежат в репозитории** (`scripts/mutations/sets/*.mjs`) — не в
/tmp: набор, который никто не видит, завтра потеряется.

**Гейт требует:**
- выжившая мутация (смоук зелёный) — провал;
- мутация, которая НЕ ПРИМЕНИЛАСЬ (строка не найдена) — провал: набор
  устарел, его надо чинить, а не молча пропускать;
- смоук, который ЗАВИС — провал.

### Живое устройство — «это работает у человека»

`scripts/device-accept.mjs` + `docs/testing/device-acceptance.md`. Проверяет
то, чего не видит ни один модульный тест: связность компонента с владельцами,
жизненный цикл, реальные жесты.

## Команды

```bash
npm run build                 # гейты + все смоуки + vite + boot-smoke
npm run quality               # build + мутации + покрытие  (полный запуск)
npm run gate:mutations        # только мутационное тестирование (13 c)
npm run gate:feature-coverage # только покрытие
npm run smoke:<имя>           # один смоук
```

Мутационное тестирование — в CI (`.github/workflows/ci.yml` ✔): 13 секунд
не могут быть причиной «проверки отложим на потом».

## Правила для новой фичи

1. Фича = `src/features/<имя>.js`. Состояние — у владельца (ADR-004), не в
   компоненте. Эффекты — явный `deps`.
2. **Смоук обязателен** (иначе гейт покрытия упадёт). Смоук проверяет
   поведение через публичный API.
3. **Набор мутаций обязателен**: 3-8 ключевых поломок, которые смоук обязан
   поймать. Начните с «что будет, если условие перестанет работать».
4. Свойства — когда есть класс входов (строки, ключи, числа).
5. Проверка на устройстве — если трогаете UI, навигацию или ввод.

## Уроки, оплаченные временем (20.10.2026)

За один день мутационное тестирование вскрыло девять классов слабых
проверок. Каждый из них молча оставлял фичу без настоящей проверки:

1. **Проверка, отложенная от своих данных** — «счётчик сброшен» проверялось
   на значении, которое и так было нулевым.
2. **Проверка-декорация** — `|| true` в конце условия: всегда зелёная.
3. **Незначимое начальное значение** — `picked = null` до проверки
   «пикер закрылся»: и без закрытия проходило.
4. **Стенд, повторяющий НЕ поведение владельца** — `removeById` в стенде
   ЗАМЕНЯЛ массив, а настоящий chat-store делает `splice`; проверка «кэш без
   удалённого» проходила всегда.
5. **Мутация не в той функции** — одинаковая строка в двух модулях: паттерн
   применился не туда.
6. **Эквивалентная мутация** — `allowCreate || allowCreate` не меняет
   поведения; ловить её бессмысленно (убрали, а не «доусилили» смоук).
7. **Эталон == реализация** — свойство с тем же правилом не отличает «позвали
   Rust» от «посчитали сами».
8. **Фича без смоука** — `features/drafts.js` и `features/group-avatars.js`
   прожили без проверок; в `group-avatars.js` из-за этого скрывался живой баг
   (`groupKeyOf(ctx, ...)` — `ReferenceError` глотал catch, и heal-запрос/ответ
   молча не работали).
9. **Мок, который проверял мимо** — `export default globalThis.__CRYPTO__`
   захватывает значение ПРИ ИМПОРТЕ; если мок выставлялся позже, проверки
   шли мимо (фича получала `undefined` и падала в catch).

Каждый пункт — это не «не повторять ошибку», а **гейт**, который ловит
следующий такой случай: мутационный (1-7), покрытия (8), живой мутацией
(9 — проверено негативным тестом: смоук краснеет).

### Вторая волна (20.10.2026, вечер): владельцы состояния

Наборы для владельцев (chat/sending/identity/folders/groups/mailbox/relay/
notes/channels/messages/session/contacts) вскрыли ещё четыре класса:

10. **У владельца нет СВОЕГО смоука — покрытие случайное.** `notes-store.js`
    и `channels-store.js` покрывались лишь ПОПУТНО (смоук фичи дёргал
    `store.add` в своём стенде). Семантика владельца (откат при ошибке
    записи, дедуп по id, ЗАМЕНА постов, обнуление счётчика, полный сброс)
    не проверялась нигде. Лечится гейтом покрытия: смоук владельца —
    отдельный файл, набор мутаций ссылается именно на него.
11. **Мутация, вставляющая no-op, эквивалентна.** `void 0;` В НАЧАЛЕ тела
    метода не ломает код — тело продолжает выполняться. Бить надо по ТЕЛУ:
    `list.push(note)` → `void 0;`, а не `add(email, note) {` → `void 0;`.
12. **«Ключ отсутствует» ≠ «состояние чистое».** Проверка «`getGroupKey('g1')`
    === undefined» проходит и при мутации, оставляющей чужие ключи. Проверять
    ФОРМУ состояния (`Object.keys(map).length === 0`), а не отдельные значения.
13. **Два инварианта в одном сценарии.** `clearUnread` проверялся на счётчике,
    который и так был нулём (после `setUnread('c1', 0)`) → проверка-декорация.
    Перед обнулением нужен НЕНУЛЕВОЙ счётчик.

Проверка-декорация (13) и «нет своего смоука» (10) — самые дорогие: они
прячутся именно там, где состояние считается «очевидным».

### Третья волна (20.10.2026, ночь): бэклог закрыт, 559 мутаций

Добивание бэклога наборов (45 → 0 смоуков без набора) вскрыло ещё четыре
класса — и один из них нашёл НАСТОЯЩУЮ дыру в коде, а не в тесте:

14. **Проверка, которая смотрит не туда.** В `mailbox-api-deps-smoke` стояло
    `check('loadGroups: ctx доехал', groupsSpy.calls.at(-1).ctx === appCtx)` —
    но `at(-1)` брал ПОСЛЕДНИЙ вызов, а после `loadGroups` шёл
    `loadGroupMessages` → проверка фактически смотрела на следующий вызов и
    была зелёной при СЛОМАННОМ `loadGroups`. Лечится снимком индекса:
    `calls[gBefore]`, где `gBefore` — длина массива ДО вызова.
15. **Модуль без своего смоука вовсе — но «покрытый».** Владельцы таймеров
    звонков (`call-clock`, `call-ring`, `call-terminal`, `call-watchdog`,
    `timing`, `call-idle`, `call-resend`) упоминались в смоуке `calls-deps`,
    но ТОЛЬКО как список файлов: ни одна их ветка не проверялась. Написан
    `call-owners-smoke` (46 утверждений): незакрытый интервал держит
    событийный цикл, незакрытый таймер гудка звонит через минуту после отбоя,
    а незатухающие повторы ретрансляции — это инцидент 12.10 (лавина писем).
16. **Проверка-декорация через `at(-1)` и через ЗНАЧЕНИЕ ДО.** Своё письмо
    отбрасывалось «по отсутствию ключа пира», а не по сравнению с `myEmail` —
    сценарий был зелёным и при сломанном сравнении. Для «своё письмо» нужен
    ключ СВОЕГО адреса, иначе тест проходит по чужой ветке.
17. **Эквивалентность по СПЕЦИФИКАЦИИ, а не по коду.** `atob` (WHATWG
    forgiving-base64) терпит пробелы и отсутствие пэйдинга → мутации
    «вырезать `.replace(/\s+/g,'')`» и «не восстанавливать `=`» ЭКВИВАЛЕНТНЫ
    и убраны из набора (ловить их бессмысленно — врать о покрытии).

Отдельно: **договор wire-формата был неполон.** В фикстуре
`m0-wire-contract.json` не было кейса «`text` есть, метки `vault:1` нет» —
при мутации «метка не проверяется» JS-сторона принимала такой JSON за
конверт, и гейт паритета этого не видел. Кейс добавлен в ОБЩУЮ фикстуру
(её читает и Rust-тест) → паритет теперь проверяет и этот случай.

### Итог третьей волны

- 87 наборов мутаций, **559 мутаций, все пойманы**, 102 с на полный прогон;
- **0 фич без смоука, 0 смоуков без набора мутаций** (ратчет покрытия пуст);
- `boot-smoke` (гейт рендера СОБРАННОГО приложения) исключён из требования
  «у смоука есть набор» с причиной: мутация в исходнике видна только после
  `vite build` — мутационная проверка бандла остаётся отдельной задачей;
- новый смоук `call-owners-smoke` (владельцы таймеров) — 46 утверждений.

**Правило, которое стоит запомнить:** мутационный гейт полезен ровно настолько,
насколько честно сделаны мутации. Мутaция должна ЗАМЕНЯТЬ решение, а не
вставлять рядом `void 0;`; эквивалентные мутации — убирать, а не «доусиливать»
смоук под них; выжившая мутация — это не «не поймали», а «смоук ничего не
проверяет».

### Четвёртая волна (20.10.2026, ночь): RUST-ядро и гигиена текста

Мутационный гейт закрыл JS-сторону, но **Rust-ядро — то, куда W4 переносит
решения о протоколе — проверялось ТОЛЬКО обычными тестами**. Обычный тест не
отвечает на вопрос «а он вообще что-то проверяет?». Построен гейт
`scripts/rust-mutation-gate.mjs` (36 мутаций в 4 наборах: ephemeral, incoming,
filter, messages, crypto) и он сразу нашёл **три настоящих пробела**:

18. **Тест на переполнение не переполнял.** Проверка «огромный TTL
    насыщается, а не переливается» брала `i64::MAX / 1000` — а это значение
    при умножении на 1000 ВМЕЩАЕТСЯ в `i64`, то есть переполнения не было и
    тест был зелёным и при обычном перемножении без насыщения. Мутация
    «снять `saturating_mul`» оставалась зелёной — то есть тест проверял не
    то, что заявлял.
19. **Формат fingerprint не проверялся.** Релей-сервер сверяет fp издателя с
    fp, привязанным к read-токену; несовпадение = 403 «token bound to another
    account» для того же ключа. Тест проверял «есть двоеточие и звёздочки» —
    на этом зелёном держалась поломка «взяли 4 байта вместо 8» и «склеили
    без разделителей».
20. **Длина ключа голоса не проверялась.** Тест на плохой ключ брал `"zz"` —
    это не hex, он не декодируется ВООБЩЕ, и проверка длины (строго 32 байта)
    не выполнялась. Плюс не проверялось, что ключ зависит от `info`.

Добавлены также: тест «`store_incoming` сообщает о дубле» (иначе уведомление о
новом письме приходило бы на каждую переотправку), тест на пустое имя в
заголовке и кейс в общей wire-фикстуре «`type` НЕ `call_*` + `call_id` → всё
равно сообщение» (его не было — а именно этот случай ловит мутацию «call по
наличию `call_id`»).

Отдельно: **гигиена текста.** Иероглифы в русском тексте появлялись пять раз
за сессию (в коммите, в модуле, в журнале, в смоуке, в черновике) — разовый
прогон по репозиторию делался и не помогал. Теперь это гейт
`scripts/hygiene-gate.mjs` (+ шаг в CI): ищет CJK/кана/хангыль и битые байты
(U+FFFD) вне `src/locales/zh.js` и вне строки `language_zh` (название языка в
выпадающем списке — там китайский законен).

## Чего проверки НЕ делают

- Не заменяют живую приёмку: статика не знает про Android WebView, про
  long-press с `clientX/Y = 0`, про то, что `computed` без реактивных
  зависимостей кэшируется навсегда.
- Не ловят «фича есть, но ею никто не пользуется» — для этого нужен
  сценарий пользователя, а не тест.
- Не дают права ослаблять потолки: ратчеты только затягиваются.
