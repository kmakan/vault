# ADR-001: Декомпозиция фронтенда (App.vue) с минимальной связанностью

**Статус:** принято (13.10.2026) · **Ветка:** fix/recovery-resilience · **Автор:** PM (Cline)

## Контекст

`vault-desktop/src/App.vue` — монолит: **9531 строка** (template 1–890, script 891–6988, style 6990+), **179 полей `data()`**, **172 многострочных inline-метода**. Vue 3.5.39, Options API, без Pinia.

Изоляция фич **частично** уже сделана: 19 модулей в `features/*`, 133 метода-делегата в App.vue. **НО** каждая фича получает `ctx` = весь экземпляр App.vue и напрямую читает/пишет **~200+ полей** (`ctx.email` — 66 обращений, `ctx.currentCall` — 38, `ctx.peerKeys` — 34 …) и вызывает методы App.vue (`ctx.showToast`, `ctx.t`, `ctx.saveChatCache`). Это **двусторонняя связанность через shared mutable god-object**.

## Решение (инкрементальное, без big-bang)

**Цель (приоритет юзера):** правка кода одной фичи не должна сказываться на других. Минимальная связанность между файлами.

**Стратегия:** последовательная выноска inline-логики App.vue в `features/*.js` по доменам, шаг за шагом, с зелёными смоук-тестами на каждом коммите. App.vue уменьшается к тонкому слою делегатов + шаблону. Каждый домен — отдельный коммит = отдельная точка diff для регресс-сравнения.

**Почему НЕ store/Pinia (на данном этапе):**
- Полное разъединение состояния (179 полей + привязки шаблона 890 строк) = big-bang rewrite живого продукта. Доставка только что починена и принята (0.1.222) — регрессия недопустима.
- Файловое разделение уже даёт главный практический эффект, которого хочет юзер: правка `features/attachments.js` не может случайно сломать логику `features/calls.js` — они в разных файлах с разными функциями, а 13 смоуки ловят регрессии.
- Остаточная связанность по состоянию (shared ctx) — реальна, но это **отдельный, более крупный** фазис. Зафиксировано как backlog, НЕ смешивается с этим.

## Порядок доменов (по риск/ценность)

1. **Вложения** (пилот): `handleFileSelect` 238, `sendAudioMessage` 110, `fetchDodAttachment` 61, `downloadAttachment`. Самодостаточный (файлы/аудио/скачивание), НЕ на критическом пути доставки → низкий риск, доказывает паттерн.
2. Загрузка/отправка сообщений: `loadMessages` 512, `sendMessage` 281, `loadGroupMessages` 280, `loadEmails` 142. Высокая ценность (ядро), выше риск — после пилота.
3. Прочие домены (инвайты, редактирование, реакции, …) по мелочи.

## Критерий приёмки каждого шага

- `node scripts/<domain>-smoke` (если есть) + все 13 смоуков зелёные.
- `npm run build` зелёный.
- `cargo check --lib` без ошибок.
- Diff узкий: только вынос логики, поведение идентично (рефакторинг, не фича — см. правило «рефакторинг не смешивать с фичами»).

## Остаточная связанность (осознанно НЕ решается здесь)

Фичи-делегаты продолжают получать `ctx`. Полное декoupling состояния (Pinia store по доменам / сужение контракта `ctx`) — отдельная большая инициатива в backlog. Требует: выноса `data()`-полей в domain-store + привязки шаблона. Высокий риск → только после стабилизации и с отдельным планом.
