# ADR-001: модель связности и её границы

Статус: действует. Сопровождает код `vault-desktop/src/features/`.

## Проблема, которую решает

`App.vue` — компонент Options API с 212 полями состояния. Фичи из
`src/features/` вызывались с `ctx` — ссылкой на **весь** экземпляр:

```js
export async function sendMessage(ctx, chat) { /* ...ctx.activeChat, ctx.peerKeys... */ }
```

Формально каждая функция жмёт 5–15 полей. Фактически ей доступны все
поля экземпляра — на пике это было 212.
Отсюда заявленная цель ADR-001 («правка одной фичи не задевает соседние»)
была недостижима **по учебу**: правишь `callState` — падает `handleCallSignal`,
который к `callState` вроде бы и не относился.

Хуже того, при `ctx` ошибка была **тихой**: `ctx.нетТакогоПоля` возвращает
`undefined`, выражение уходит в `NaN`, и падение приходит позже и в другом
месте. Это подтверждено тестом `scripts/calls-deps-smoke.mjs`.

## Правило

Зависимости перечисляются **в сигнатуре**:

```js
export async function toggleCallMute({ callMuted, currentCall }) { … return muted }
```

Деструктурированный параметр не создаёт свободных имён, поэтому граница
**жёсткая на уровне языка**: обращение к полю вне списка даёт
`ReferenceError` в месте вызова, а не тихий `undefined` в другом файле.

## Что делать с состоянием

Фича не пишет в состояние компонента. Она **возвращает** новое значение,
а `App.vue` присваивает:

```js
toggleCallMute() {
  this.callMuted = CallsFeature.toggleCallMute({
    callMuted: this.callMuted, currentCall: this.currentCall,
  });
}
```

Состояние принадлежит компоненту. Иначе правка фичи меняет данные из-под
компонента, и это не видно в коде компонента.

### Осторожно с методами компонента

`this.showToast` **нельзя** передать ссылкой — метод потеряет `this` и упадёт
на первом же обращении к состоянию. Передаётся обёрткой:

```js
showToast: (m, ms) => this.showToast(m, ms)
```

## Границы: что намеренно остаётся на `ctx`

Не всё стоит чистить. Перечисленные ниже функции **оставлены как есть
сознательно**, и это не долг:

| Модуль | Функция | Почему не трогаем |
|---|---|---|
| `calls.js` | `handleCallSignal`, `startCall`, `hangup`, `acceptCall`, `recordCallEvent` | Машина состояний звонка + крипто-материал (`_pendingKemct`, `_pendingSenderEk`, `peerPqKeys`). Ошибка здесь — это не «не та кнопка», а сломанное рукопожатие и утечка в неверный момент |
| `attachments.js` | `fetchDodAttachment`, `downloadAttachment` | Докачка вложений с проверкой ref-mismatch; ошибка тиха и приводит к чужому контенту. Обёртка `downloadDodAttachment` развязывается только внедрением зависимости — отдельной итерацией |
| `send.js` | `sendMessage` | Крипто-путь: шифрование → конверт → SMTP. Целостность конверта важнее строчки в отчёте |
| `messages.js` | `loadMessages` | Слияние истории, курсоры, tombstone. Разбиение меняет порядок операций |

Правило для ревьюера: **если функция не в этом списке и не трогает
крипто-материал/машину состояний — её можно и нужно переводить на явные
зависимости.**

## Как это контролируется

`scripts/ctx-coupling-gate.mjs` + `scripts/ctx-coupling-baseline.json`,
встроены в `npm run build` рядом с `check-template.cjs`. Гейт падает, если:

* суммарные `ctx`-ссылки в `features/` выросли;
* вырос любой отдельный модуль;
* добавилось новое поле в `ctx`.

Уменьшение — всегда норма. Осознанное изменение baseline делается явно и
попадает в git как решение:

```bash
node scripts/ctx-coupling-gate.mjs --write
```

Текущее состояние (14.10.2026): **1217 ctx-ссылок, 209 уникальных полей,
151 функция из 208**. Для сравнения: до начала работы было 1239 ссылок и
212 полей.

## Что проверяет контракт

`scripts/calls-deps-smoke.mjs` — Proxy фиксирует фактически читаемые поля и
требует совпадения с объявленным набором; исходник проверяется на
отсутствие `ctx` в переведённых функциях; отдельно зафиксирован механизм
жёсткой границы (жёсткий отказ vs молчаливый `ctx`).

## Чего гейт НЕ ловит

Он меряет **количество** `ctx`-ссылок, а не смысл. Написать
`ctx.callSpeaker` вместо `ctx.callState` — количество не изменится. Поэтому
гейт — это страховка от отката, а не доказательство корректности. Правильность
проверяют смоуки и живая приёмка.
