# Sfera — релиз

Порядок для десктопа и будущих мобильных сборок. Общие правила репозитория —
`docs/RELEASE-RUNBOOK.md`; здесь только отличия Sfera.

## Версия и тег

- Версия: `sfera/src-tauri/tauri.conf.json` (и `package.json`, если меняется UI).
- Тег: **`sfera-vX.Y.Z`** (у мессенджера — `vX.Y.Z`, чтобы теги не путались).
- Тег ставится на коммит, а не на «хвост» ветки; после push проверить, что
  `sfera-vX.Y.Z` на обоих ремоутах указывает на один коммит.

## Десктоп

```bash
cd ~/whisper/sfera
./scripts/build-desktop.sh
```

Скрипт прогоняет контрактные гейты, собирает фронтенд и Tauri. Артефакты:

```
sfera/src-tauri/target/release/bundle/
```

Копировать в `/home/maksim/vault-releases/sfera/<версия>/` вместе с SHA256.
Публиковать только сборку, прошедшую ручную проверку по чек-листу
`docs/DESKTOP-ACCEPTANCE.md`.

## Android

Пока не настроен `gen/android` (`npm run tauri android init` — отдельная
партия). После инициализации:

- package id `com.vault.sfera`, **свой** keystore (не мессенджера);
- APK — RuStore и прямой канал, AAB — Google Play;
- проверка JNI/DEX — тем же принципом, что в мессенджере (R8 не должен
  вырезать мост);
- подпись и ключи — в `~/.hermes/secrets`, в git не попадают.

## Магазины

- Один магазин — один листинг на продукт. Vault и Sfera не объединяются.
- Название: **Sfera**; описание и скриншоты — `sfera/store/`.
- Категория: «Социальные сети». Возрастной рейтинг — по контенту, не ниже
  мессенджера.
- В описании честно указать: контент хранится у пользователя или в хранилище
  Vault; приватные посты E2E; публичные страницы — публичны по выбору владельца.

## Перед публикацией

1. `cargo test --workspace` в `sfera` — зелёный.
2. `npm run test:contract` — зелёный.
3. `npm run build` — зелёный.
4. Ручной чек-лист десктопа пройден.
5. `kernel-consumers` в CI — зелёный (мессенджер не сломан).
