# Sfera Desktop — чек-лист приёмки

Ручная проверка перед показом и релизом. Автоматические гейты
(`test:contract`, `cargo test --workspace`) обязательны, но не заменяют этот
список: они не видят окно, шрифты и раскладку.

## Запуск

```bash
cd ~/whisper/sfera
npm run tauri dev
```

Приложение берёт ключ из `~/.vault/keys` (или `VAULT_KEYS_DIR`). Если ключа
нет — окно не откроется и будет понятная ошибка; это ожидаемое поведение.

## Основной проход

- [ ] Окно открывается, заголовок **Sfera**, без белого экрана и без крэша.
- [ ] Пять вкладок: Лента, Контакты, Создать, Хранилище, Профиль.
- [x] Стартовая вкладка — «Лента»; переключение не теряет состояние (21.11: найден и исправлен рассинхрон reactive-состояния, `8b14b11`).
- [ ] «Лента»: пустое состояние «Пока нет постов от ваших контактов».
- [x] «Лента»: у поста с медиа видны кнопки типа и размера; клик открывает предпросмотр (23.11).
- [x] Плашка синхронизации показывает время обновления и число в очереди; без
      транспорта честно сказано «транспорт не подключён» (23.11).
- [x] Миниатюры: плитки галереи и медиа в ленте показывают маленький JPEG, полный файл читается только по клику (23.11).
- [ ] «Контакты»: пустое состояние «Контактов пока нет» (пока нет данных).
- [x] «Контакты → Сферы»: виден состав и эпоха, «Изменить состав» сохраняет новый набор; сферы контакта считаются по фактическому составу (23.11).
- [x] «Контакты»: у принятого контакта выбирается роль из списка, подписанного
      правами из Rust; состояние, сферы и точечные права при смене роли не
      затираются (23.11).
- [ ] «Создать»: поле ввода, адресат «Сначала создайте сферу в контактах»,
      кнопка «Опубликовать» недоступна.
- [x] «Создать»: аудитория выбирается явно — пустой выбор и первая сфера
      «по умолчанию» не публикуются; сразу после создания сферы она выбирается
      в форме (23.11).
- [x] «Создать»: «Прикрепить файл» шифрует вложение и добавляет его к посту; после публикации статус «Опубликовано» (23.11).
- [x] Черновик композера сохраняется при переключении вкладок и перезапуске; после публикации очищается (23.11).
- [x] «Хранилище»: тип `Local`, квота «Без ограничения», бейдж `Range` (21.11).
- [x] «Хранилище → Добавить файл»: файл шифруется в VAULTBLOB1 до записи, ключ возвращается отдельно для E2E (21.11, `9d419fb`).
- [x] Загруженный файл прикрепляется к посту: `MediaRef` и E2E-манифест собираются в Rust (21.11, `dd79580`).
- [x] «Хранилище → Мои файлы»: галерея загруженного, удаление из списка (21.11, `7d97996`).
- [x] «Хранилище → Мои файлы»: клик по файлу открывает предпросмотр; изображение и документы читаются через `social_library_open`, аудио и видео играют по адресу от `social_library_stream` и догружаются через `sfera-media` Range (24.11). Для документов честно сказано, что встроенного просмотра нет.
- [ ] Живая приёмка Range в окне: перемотать видео/аудио больше 8 МБ, убедиться, что запросы идут с `Range` и ответы `206`, а ключ и локальный путь не видны в URL (24.11).
- [ ] «Профиль»: «Аккаунт: Не связан», отпечаток **ключа устройства**,
      подсказка про QR. Отпечаток не выдаётся за аккаунт мессенджера.
- [x] «Профиль → Мой профиль»: имя, био и до 8 ссылок; сохранение подписывается в Rust, статус «Профиль сохранён» (23.11).
- [x] «Профиль → Моя стена»: свои посты из ленты (`is_mine` считает Rust); в ленте есть фильтр «Мои» (23.11).
- [x] «Профиль → Мой профиль → Выбрать аватар»: изображение шифруется и кладётся отдельным блобом, в профиль уходит только ссылка; «Убрать аватар» очищает выбор до сохранения (23.11).

- [ ] Мессенджер: «Настройки → Профиль → Связать Sfera» → вставить ключ
      устройства из Sfera → «Показать QR-код».
- [ ] Sfera: «Профиль → Код связывания» → вставить QR → «Связать».
- [ ] После связывания в профиле один ID: `account_fp` (Ed25519); X25519
      ушёл в строку «Ключ шифрования».
- [ ] Перезапуск Sfera: связывание сохраняется, цепочка проверяется повторно.
- [ ] Подменённый QR не становится «связанным»: проверка цепочки в Rust.

## Известные пробелы MVP (не дефекты приёмки)

- Перенос графа зависит от ключей подписи контактов: в bundle попадают только
  контакты, обновившие приложение. Остальные честно не переносятся.
- Приглашения и сферы подключены к UI (21.11); новые контакты пока приходят
  по QR вне приложения.
- Исходящая доставка подключена через отдельные `SFERA_SMTP_*` (24.11). Пока
  они не заданы, статус честно сообщает об отсутствии транспорта; запуск
  `social_sync_outbox` явный. Наличие порта не означает доставку: успех фиксирует
  только ответ SMTP-сервера. Gmail может разрезать длинный JSON-конверт на
  строки по 76 байт прямо в text/plain: приёмник читает полное MIME-письмо
  через `BODY.PEEK[]`, декодирует text/plain и восстанавливает единственный
  JSON-объект. Обычные тела по-прежнему не скачиваются, `\\Seen` не меняется.
- Живая двусторонняя приёмка обсуждения (26.11): отдельные тестовые экземпляры
  Alice и Bob, Gmail SMTP/IMAP, без личного и RuStore demo аккаунтов. Bob
  отправил зашифрованный submission, Alice приняла его и выпустила подписанное
  attestation, Bob получил его: `accepted=1, rejected=0, comments=1, event=true`.
  Повторный UID не создаёт новое уведомление; `SyncStatusDto.sent` отражает
  только SMTP-accept, не прочтение. Отчёт UI разделяет профили, комментарии и
  реакции. Живой профильный цикл и фоновые системные уведомления — отдельные
  проверки; фоновый IMAP-монитор не запускается.
- Роль контакта меняется локально: `social-rights` пересчитывает права, но
  участник не получает E2E-конверт с новой ролью — это отдельный формат,
  общий SMTP-порт его сам по себе не добавляет.
- Аватар редактируется локально: файл шифруется и попадает в «Мои файлы»
  (ключ живёт в каталоге Rust), поэтому превью работает и после перезапуска.
  Профиль и манифест аватара уходят адресным E2E-конвертом. Приёмник может
  расшифровать профиль вызовом `social_receive_profile` и открыть аватар по
  `profile_id`; ключ и манифест не передаются в JS. Явный `social_receive_inbox`
  читает INBOX по `SFERA_IMAP_*`: сначала только PEEK-тему, полное PEEK-тело —
  только для `sfera-profile:*`. Чужие тела и `STORE \\Seen` не затрагиваются.
  Локальный end-to-end принял реальный E2E-профиль; внешний почтовый провайдер
  и двусторонняя доставка ещё требуют живой приёмки. В «Контактах» кнопка
  «Проверить почту» запускает цикл и показывает принятые имя/аватар по
  `profile_id`; ключи не передаются в JS. Книга и манифесты сохраняются в
  `keys/received_profiles.json` (0600) и восстанавливаются после перезапуска;
  подписи и соответствие аватара проверяются повторно. Повреждённый файл —
  ошибка, а не молчаливая потеря книги. Внешняя живая приёмка всё ещё отдельна.
- Медиа загружается, шифруется, публикуется с постом и показывается в галерее
  (21.11). Предпросмотр открывает изображения, аудио и видео из своего каталога
  (23.11); в ленте медиа своего поста тоже открывается. Аудио и видео читаются
  кусками через `sfera-media`: WebView шлёт `Range`, Rust отдаёт `206` с
  `Content-Range`, один ответ ограничен 1 МБ; потолок 64 МБ на них не
  действует. Изображения и документы по-прежнему читаются целиком и
  ограничены 64 МБ. Миниатюры (JPEG до 512 px) создаются при загрузке; у файлов,
  загруженных раньше, превью не будет. Чужие посты ждут подключения манифеста
  из E2E-конверта.
