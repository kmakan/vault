# Sfera — руководство пользователя

**Статус:** черновик для сайта, не публиковать до приёмки текущей сборки.
**Версия продукта:** 0.1.0 (desktop, Linux).
**Дата:** 28.11.2026.

Это руководство для человека, который устанавливает Sfera и пользуется ей,
а не для разработчика. Технические детали, которых пользователь не видит,
здесь намеренно опущены; ограничения названы честно.

---

## 1. Что такое Sfera

Sfera — распределённая социальная сеть. Посты, комментарии, профили и файлы
ходят через вашу обычную почту, а не через центральный сервер соцсети.
Ключи создаются на вашем устройстве; чужой сервер не хранит вашу ленту.

Sfera — отдельное приложение, не замена мессенджеру Vault:

- **Vault** — личные и групповые чаты, звонки, вложения.
- **Sfera** — лента, сферы (круги получателей), публичные страницы,
  обсуждения под постами.

Аккаунт Sfera можно связать с Vault по QR-коду. Связывание удобно для
контактов и профиля, но Sfera работает и как самостоятельное устройство.

### Что важно понимать сразу

- **Личные посты шифруются** для выбранной аудитории. Их не читает ни
  почтовый провайдер, ни мы.
- **Публичный пост публичен.** Его может прочитать любой, кому вы дали
  ссылку, и он не защищён E2E-шифрованием.
- **Потеря ключа устройства = потеря личности в Sfera.** Восстановления
  аккаунта «по почте» нет: ключ хранится только у вас.
- **Почта — транспорт.** Провайдер видит факт письма, адреса и время, даже
  если тело зашифровано. Для Sfera лучше отдельный ящик и пароль приложения.

## 2. Установка и первый запуск

### Готовой сборкой

1. Скачайте сборку Sfera для своей системы со страницы загрузки.
2. Запустите приложение. Отдельная регистрация не нужна.
3. При первом запуске Sfera создаёт **ключ устройства** и показывает ваш
   отпечаток в разделе «Профиль».
4. Сразу сделайте резервную копию каталога данных (см. §3). Это ваша
   единственная копия личности.

Android-сборка пока не выпущена. Не устанавливайте APK из случайных
источников: официальная сборка появится отдельно.

### Из исходников (для разработки)

```bash
cd ~/whisper/sfera
npm ci
npm run tauri dev
```

Сборка desktop-артефактов:

```bash
cd ~/whisper/sfera
./scripts/build-desktop.sh
```

Артефакты появятся в `sfera/src-tauri/target/release/bundle/`.

### Первый экран

После запуска открывается «Лента». Пока контактов и постов нет, это
нормально: Sfera не подставляет чужие записи и не показывает «рекомендации».
Сначала настройте почту и добавьте контакты.

## 3. Где Sfera хранит данные

На Linux каталог приложения обычно:

```
~/.local/share/com.vault.sfera/
```

Внутри:

- `identity.json` — ключ устройства (Ed25519). **Самое важное.**
- `keys/encryption.json` — ключ шифрования Sfera (X25519 + PQ).
- `keys/received_profiles.json` — принятые профили контактов.
- `blobs/` — зашифрованные файлы хранилища.
- `sfera_link.json` — связывание с аккаунтом Vault, если выполнено.

Правила:

- не удаляйте `identity.json` и `keys/` при «переустановке»;
- не передавайте эти файлы никому;
- копируйте каталог только на собственный носитель;
- при потере каталога восстановить личность Sfera нельзя.

Перед обновлением приложения закройте Sfera и скопируйте каталог целиком.

## 4. Настройка почты

Сейчас почта настраивается **переменными окружения** при запуске, а не
экраном в приложении. Это ограничение текущей сборки; экран настроек
появится позже.

Нужны отдельные параметры для отправки (SMTP) и приёма (IMAP). Используйте
**пароль приложения**, а не основной пароль от почты.

### Отправка

```bash
export SFERA_SMTP_EMAIL="you@example.com"
export SFERA_SMTP_PASSWORD="app-password"
export SFERA_SMTP_SERVER="smtp.example.com"
export SFERA_SMTP_PORT="465"
```

### Приём

```bash
export SFERA_IMAP_EMAIL="you@example.com"
export SFERA_IMAP_PASSWORD="app-password"
export SFERA_IMAP_SERVER="imap.example.com"
export SFERA_IMAP_PORT="993"
```

### Ориентиры для популярных провайдеров

- **Gmail:** `smtp.gmail.com`, порт `587`; `imap.gmail.com`, порт `993`;
  нужен пароль приложения (включите двухфакторную аутентификацию).
- **Яндекс.Почта:** `smtp.yandex.ru`, порт `465`; `imap.yandex.ru`, порт
  `993`; нужен пароль приложения и разрешение IMAP/SMTP в настройках почты.

Точные значения всегда смотрите в справке своего провайдера: он может
требовать отдельное разрешение или ограничивать частоту писем.

### Проверка

1. Запустите Sfera с переменными окружения.
2. В «Контактах» нажмите «Проверить почту». Приложение прочитает только
   свои служебные письма, не трогая остальной ящик и не ставя `\Seen`.
3. В «Ленте» посмотрите плашку синхронизации: она честно показывает число
   писем в очереди и было ли отправлено.

Если транспорта нет, Sfera не делает вид, что пост доставлен: статус
сообщает «транспорт не подключён», а публикация остаётся локальной.

### Безопасность почты

- Не используйте основной пароль от ящика.
- Храните пароль приложения в менеджере паролей, не в истории команд.
- Если ящик скомпрометирован — отзовите пароль приложения и смените ключи
  Sfera.
- Один и тот же ящик можно использовать в Vault и Sfera, но лучше
  разделять: так проще понять, кто отправил письмо.

## 5. Интерфейс

Пять вкладок:

1. **Лента** — посты контактов и ваши записи.
2. **Контакты** — принятые люди, приглашения, сферы и роли.
3. **Создать** — новый пост, вложение, сфера.
4. **Хранилище** — ваши зашифрованные файлы.
5. **Профиль** — имя, био, ссылки, аватар, стена, связывание с Vault,
   язык и тема.

Горячие клавиши: `Ctrl+1`…`Ctrl+5` (на macOS — `Cmd`) переключают вкладки.
`Esc` закрывает предпросмотр файла.

Темы: Dark, Light, Amber. Языки: русский, English, 中文.

## 6. Контакты и сферы

### Что такое контакт

Контакт — это человек, чей ключ вы приняли и проверили. Sfera показывает
**отпечаток** (длинную строку из букв и цифр). Отпечаток — не «ник» и не
адрес почты: по нему проверяют, что вы говорите с тем же человеком.

### Как добавить контакт

1. Получите приглашение — QR-код или JSON-код от человека.
2. Откройте «Контакты → Приглашение».
3. Вставьте код целиком и нажмите «Принять приглашение».
4. Sfera проверит подпись и покажет контакт в списке.

Приглашение можно принять только один раз. Если код «уже был», контакт
уже добавлен. Если код неверный, Sfera не создаёт контакт «на всякий
случай».

Новые контакты в текущей сборке приходят по QR/коду; автоматического
поиска людей по адресу почты нет. Это сознательно: Sfera не превращается
в глобальный каталог.

### Сферы

**Сфера** — именованный круг получателей, например «Семья», «Работа»,
«Друзья». Пост адресуется сфере, а не отдельному списку «всем».

- Создайте сферу в «Контактах» или в «Создать».
- Отметьте участников.
- Выберите сферу при публикации.

Сфера — не просто ярлык: у неё есть **эпоха** и ключ. Когда состав меняется,
Sfera меняет ключ, чтобы новый участник не читал старые посты, а удалённый
не читал новые. Поэтому после изменения состава старые записи могут
остаться доступными только тем, у кого был старый ключ.

### Роли

У контакта есть роль. Роль задаёт, что человек может видеть и делать:
медиа, реакции, историю, личный чат. Список ролей и подписи приходят из
ядра Sfera; интерфейс не придумывает права сам.

В текущей сборке смена роли действует **локально**. Другой участник не
получает отдельного уведомления о новой роли. Это ограничение, а не
«скрытая настройка».

## 7. Публикации, лента и обсуждения

### Как опубликовать пост

1. Откройте «Создать».
2. Напишите текст.
3. При необходимости прикрепите файл — он шифруется до записи.
4. Выберите сферу. **Без выбранной сферы кнопка публикации недоступна.**
5. Нажмите «Опубликовать».

Черновик сохраняется при переключении вкладок и перезапуске. После
публикации он очищается.

### Лента

В ленте видны:

- ваши посты и посты контактов;
- аудитория поста (например, сфера);
- вложения с типом и размером;
- комментарии и реакции.

Фильтры: «Все», «Мои», конкретная сфера. Лента не сортируется «умным»
алгоритмом: порядок определяет время и правила ядра, а не реклама.

### Доставка

Публикация сначала локальная. Затем Sfera ставит зашифрованные конверты в
очередь и отправляет их через SMTP. Плашка синхронизации показывает:

- когда была последняя попытка;
- сколько писем в очереди;
- сколько отправлено;
- есть ли вообще транспорт.

«Отправлено» означает, что SMTP-сервер принял письмо, а не что человек
его прочитал. Это разные вещи, и Sfera не выдаёт одно за другое.

### Комментарии и реакции

Комментарий к посту подписывается и шифруется для участников обсуждения.
Владелец поста подтверждает комментарий; после этого он доходит до
комментатора как проверенное событие. Комментарии и реакции не являются
«лайками для охвата»: они не влияют на алгоритмическую ленту, которой
здесь нет.

## 8. Профиль и хранилище

### Профиль

В «Профиле» можно:

- выбрать аватар (изображение шифруется и хранится как файл);
- указать имя, био и до восьми ссылок;
- посмотреть свою стену — свои посты;
- связать Sfera с аккаунтом Vault по QR;
- переключить язык и тему.

Профиль подписывается ключом устройства. Контакты получают его адресным
конвертом; чужой профиль нельзя выдать за свой без ключа.

### Хранилище

«Хранилище» — это ваши файлы, а не облако соцсети:

- файл шифруется до записи;
- в ленте и профиле видны только ссылки и превью, ключ остаётся в ядре;
- изображения, аудио и видео открываются во встроенном просмотре;
- документы честно открываются как файл, без встроенного редактора;
- удаление убирает файл из списка приложения.

Файлы, загруженные до появления миниатюр, могут не иметь превью. Это не
ошибка потери данных.

## 9. Публичные каналы

Публичный канал — страница, которую можно читать без аккаунта Sfera.
Публичный пост **не шифруется**: это осознанно открытый контент. Приватные
сферы и личные посты остаются E2E.

Во вкладке **«Каналы»** можно создать канал, открыть его ленту и опубликовать
текстовый пост. Манифест и каждый пост подписывает Rust-ключ устройства;
повторное создание того же id не перезаписывает существующий канал.
Публикация не рассылается контактам по почте: она попадает в локальную
публичную витрину и в вашу ленту.

Что уже готово:

- подписанный манифест канала (создатель, название, описание);
- подписанные посты, привязанные к каналу и создателю;
- создание канала и публикация текста из приложения;
- витрина, которая проверяет подпись каждого поста при загрузке;
- HTTP-витрина для чтения: список каналов и лента канала;
- публичные страницы `/sfera/channels` и `/sfera/channels/<id>` на сайте;
- синхронизация с релеем по кнопке: сервер повторно проверяет подписи,
  добавляет новые посты и не удаляет уже принятые. Повтор не создаёт дубликатов.

Для синхронизации укажите HTTPS-адрес релея и выданный администратором
токен загрузки. Не отправляйте этот токен третьим лицам: он разрешает upload
на сервер. Токен и подпись постов — разные вещи: сервер всё равно проверяет,
что автор канала и каждого поста совпадает с создателем.

Чего ещё нет:

- публикации медиа через экран канала;
- комментариев к публичным постам;
- фоновой автоматической синхронизации.

Локальная витрина не означает публикацию в интернете. Канал появляется на
сайте только после явной синхронизации с подключённым к сайту релеем.

## 10. Платные каналы и монетизация (планы)

Sfera не продаёт рекламу, охват и место в алгоритмической ленте. Платными
могут быть **ресурсы и дополнительные возможности**, а не доступ к людям.

Разрешено и планируется:

- платные каналы и подписки на контент автора;
- платные стримы/эфиры (через SFU);
- хранение и релей как платные ресурсы;
- коммерческие страницы — **бесплатно**; платят только за ресурсы.

Запрещено:

- продажа охвата и «продвижение в ленте»;
- алгоритмическая лента, которая решает, кому показать пост;
- рекламный аукцион.

### Пока статус — самозанятый (НПД)

Платформа **не берёт комиссию и не проводит деньги авторов**. Автор может
сам выставить ссылку на оплату и сам подписать право доступа; Sfera не
выступает агентом и не принимает чужие деньги.

После перехода на ИП/ООО появится платёжный контур платформы: касса,
комиссия, чеки. До этого `SFERA_CREATOR_SETTLEMENTS=off`, и это не
временная кнопка в интерфейсе, а юридическое ограничение.

### Что уже готово в коде

- право доступа создателя (`CreatorEntitlement`);
- эпохные ключи канала и выдача ключа только по активному праву;
- локальное хранилище ключей канала;
- подписанное приглашение в канал (навигация, не подписка).

Чего нет: экрана покупки, платёжной кассы и пользовательского сценария
подписки. Платные каналы пока не включайте в публичное обещание.

## 11. Приватность и безопасность

### Что защищено

- Личные посты и вложения шифруются для выбранной аудитории.
- Ключи создаются и хранятся на устройстве.
- Нет центрального сервера, который хранит вашу ленту.
- Публичный профиль и публичные посты — исключение: они открыты по
  замыслу.

### Что видит почтовый провайдер

Даже с шифрованием провайдер видит:

- адрес отправителя и получателя;
- тему (в Sfera она пустая);
- время и размер письма;
- факт переписки.

Это метаданные. Sfera не обещает их скрыть: для этого нужен другой
транспорт, а не почта.

### Потеря устройства

Если устройство потеряно:

- без резервной копии ключа личность Sfera не восстановить;
- смена пароля почты не возвращает ключ;
- не отправляйте `identity.json` «в поддержку» — это ключ, а не документ.

### Подозрительные приглашения

Не принимайте код от человека, которого не знаете. Проверяйте отпечаток
по независимому каналу (голос, встреча, другой мессенджер). Sfera проверяет
подпись, но не проверяет, что за отпечатком — тот самый человек.

## 12. Ограничения текущей версии

- Только desktop; Android-сборка ещё не выпущена.
- Почта настраивается переменными окружения, без экрана настроек.
- Нет фонового монитора почты: приём запускается кнопкой «Проверить почту».
- Новые контакты — по QR/коду, без поиска по адресу.
- Смена роли контакта не рассылается другому участнику.
- Публичные каналы создаются локально; публичный сайт и релей ещё не подключены.
- Платные каналы есть в контрактах, но не в UI и не в оплате.
- Чужие медиа в постах ждут полного манифеста из E2E-конверта.
- Нет обещания доставки: успех — только ответ SMTP-сервера.

## 13. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Транспорт не подключён» | Заданы ли `SFERA_SMTP_*`; перезапущено ли приложение с ними |
| Письма не приходят | `SFERA_IMAP_*`, пароль приложения, разрешён ли IMAP у провайдера |
| Контакт не появился | Код приглашения целиком, не принят ли он раньше, верный ли QR |
| Пост не публикуется | Выбрана ли сфера; не пустой ли текст; есть ли место в хранилище |
| Вложение не открывается | Файл старый (без миниатюры) или чужой пост без манифеста |
| Приложение не запускается | Цел ли каталог данных; не повреждён ли `identity.json`; есть ли ключи |
| После переустановки «пропал» аккаунт | Каталог данных был удалён; восстановление невозможно без копии |
| Не меняется роль | Роль действует локально и не рассылается; это известное ограничение |

При ошибке не удаляйте каталог данных «для очистки»: сначала сохраните его
копию. Диагностика без секретов — отпечаток, код ошибки, время; пароль и
ключи в поддержку не отправляются.

## 14. Словарь

- **Отпечаток** — короткий производный идентификатор ключа; по нему
  сверяют собеседника.
- **Сфера** — именованный круг получателей с собственным ключом и эпохой.
- **Эпоха** — версия ключа сферы; меняется при изменении состава.
- **E2E** — шифрование от устройства отправителя до устройства получателя.
- **Конверт** — зашифрованное письмо Sfera, которое несёт событие.
- **Outbox** — локальная очередь исходящих конвертов.
- **Публичный канал** — открытая страница; контент не шифруется.
- **Право создателя** — подписанное разрешение на доступ к платному каналу.
